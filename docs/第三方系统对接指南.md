# 企业公文知识库平台 · 第三方系统对接指南

> 配套文档：《详细设计文档 V1.2》《项目架构文档》《详细功能设计文档》《接口文档（含标准规范）》
> 最后更新：2026-10-09
> 适用对象：**第三方公文系统开发者**、**部署方算力中心开发者**

---

## 1. 文档目的与边界

本指南面向需要把本平台接入自有业务系统的**第三方开发者**。平台定位为
**被集成的 RAG 引擎服务**，由**我方制定标准、第三方适配**：

- 我方负责：文档解析、切片入库、检索推理、模板库维护、导出下载接口、配置中心、运维台。
- 第三方负责：组织架构 / 部门树、用户认证、权限主数据、密级定义映射、导出渲染前端、起草工作台。
- 关键点：**密级、权限、敏感词的控制规则由我方制定标准**，第三方按标准下发上下文并适配字段。

> 集成契约（字段、枚举、模型接口）以《接口文档》v1 为冻结基线；本指南是其"如何使用"的说明。
> 在后端正式实现前，可用 `backend/mock_api/` 下的 Mock 服务提前联调（见第 11 节）。

## 3. 通用约定

### 3.1 鉴权
- 网关令牌：`Authorization: Bearer <token>` 或 mTLS。
- **终端用户身份已由第三方网关鉴权**，我方不重认证；但调用上下文（密级/权限）由网关下发，我方**服务端强制执行**过滤。

### 3.2 响应信封
所有响应统一包一层：
```json
{ "code": 0, "message": "ok", "data": { ... }, "trace_id": "..." }
```
- `code = 0` 成功；`code ≠ 0` 见第 8 节错误码。
- 错误时 `data` 通常为 `null`，错误信息在 `message`。

### 3.3 编码与格式
- 字符集 UTF-8；时间 ISO-8601（如 `2025-03-01` / `2025-03-01T10:00:00+08:00`）。
- 报文 `Content-Type: application/json`。

### 3.4 调用上下文（检索/生成必带）
检索与生成必须携带 `context`：
```json
{
  "context": {
    "caller_scope": ["scope:dept:总部", "scope:role:公文员"],
    "max_clearance": "RESTRICTED",
    "sensitive_words": ["可选：请求级覆盖词表"],
    "tenant": "可选：多租户标识"
  }
}
```
**缺失 `caller_scope` / `max_clearance` 直接返回 400**（见 R7 信任边界误用风险）。

## 4. 我方制定的标准（第三方须适配）

### 4.1 文档元数据标准（接入必带字段）
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| external_id | string | 是 | 第三方业务主键（幂等依据） |
| title | string | 是 | 标题 |
| doc_type | string | 是 | 文种：通知/通报/报告/请示/函/纪要/决定/意见 |
| issuer | string | 否 | 发文机关 |
| doc_no | string | 否 | 文号 |
| publish_date | date | 否 | 发布日期 |
| security_level | enum | 否 | 见 4.2（默认 INTERNAL） |
| permission_tags | string[] | 否 | 见 4.3（默认空） |
| owner_org | string | 否 | 归属组织 |
| source_system | string | 否 | 来源系统标识 |
| content_ref | string | 否 | 对象存储（本地文件系统 / S3 兼容） 引用；或与内联 `content` 文本二选一 |

### 4.2 密级枚举（我方标准，六级，2026-10-15 起）
| 枚举值 | 中文名 | 权重 |
|---|---|---|
| `PUBLIC` | 非密 | 1.0 |
| `INTERNAL` | 内部 | 2.0 |
| `COMMERCIAL` | 普通商密 | 2.3 |
| `CORE_COMMERCIAL` | 核心商密 | 2.7 |
| `CLASSIFIED` | 密级 | 3.0 |
| `TOP_SECRET` | 机密 | 4.0 |

> 第三方将自身分级**映射**到上述六级；检索以我方枚举判定可见上限。
> 历史四级代码（`RESTRICTED`/`SECRET`）与中文名（`机密`/`商密`…）服务端自动归一，**存量接入零改造**。

### 4.3 权限标签格式（我方标准）
元素：`scope:<type>:<value>`，`type ∈ {dept, role, user, group}`。
示例：`["scope:dept:总部", "scope:role:公文员"]`。

**可见判定（服务端强制）**：
- 切片/文档 `security_level` 的密级权重 ≤ 调用方 `max_clearance` 权重；
- 且切片/文档 `permission_tags` 与调用方 `caller_scope` 存在交集（或调用方无 scope 时仅可见无权限约束的公开内容）。

## 5. 端点详解

### 5.1 文档接入
`POST /v1/documents`
```json
{
  "docs": [
    {
      "external_id": "OA-2025-0001",
      "title": "关于汛期值班安排的通知",
      "doc_type": "通知",
      "issuer": "XX公司办公厅",
      "doc_no": "XX函〔2025〕12号",
      "publish_date": "2025-03-01",
      "security_level": "INTERNAL",
      "permission_tags": ["scope:dept:总部", "scope:role:公文员"],
      "owner_org": "办公厅",
      "source_system": "公文系统V2",
      "content_ref": "storage://docs/2025/0001.pdf"
    }
  ]
}
```
响应：
```json
{ "code": 0, "message": "ok", "data": { "accepted": 1, "failed": 0, "task_ids": ["t-abc"] }, "trace_id": "..." }
```
- 入库为**异步**，用 `GET /v1/documents/tasks/{task_id}` 查询进度/状态。
- `external_id` 重复返回 `code=409`。

### 5.2 检索
`POST /v1/retrieve`
```json
{
  "query": "安全生产责任追究",
  "context": { "caller_scope": ["scope:dept:总部", "scope:role:公文员"], "max_clearance": "RESTRICTED" },
  "top_k": 10
}
```
响应 `data`：
```json
{
  "citations": [
    {
      "chunk_id": "c-123", "doc_id": "d-1", "doc_no": "XX函〔2025〕12号",
      "title": "关于...的通知", "snippet": "...", "score": 0.91,
      "citation": { "doc_no": "...", "title": "...", "chunk_seq": 3 }
    }
  ],
  "truncated_by_security": false
}
```
> 越权/超密级结果已在服务端过滤；`truncated_by_security=true` 表示存在被过滤项（供审计/提示）。

### 5.3 推理 / 问答（起草辅助）
`POST /v1/generate`
```json
{
  "task": "draft",
  "doc_type": "通知",
  "query": "起草一份关于汛期值班安排的通知",
  "elements": { "主送": "各分公司", "要点": ["带班领导", "24小时值守"] },
  "context": { "caller_scope": ["scope:dept:总部"], "max_clearance": "RESTRICTED", "sensitive_words": ["可选覆盖词"] }
}
```
响应 `data`：
```json
{
  "answer": "各分公司：...[1]...[2]",
  "citations": [ { "marker": "[1]", "doc_no": "XX函〔2025〕12号", "title": "...", "chunk_id": "c-123", "snippet": "..." } ],
  "sensitive_hits": [ { "word": "XXX", "action": "masked", "position": [12, 15] } ],
  "hallucination_flag": false
}
```
> 生成结果**强制引用溯源**（角标 + citations）；敏感词命中在输出后处理并回报 `sensitive_hits`。

### 5.4 模板库（我方维护，第三方可导入）
- `GET /v1/templates`、`POST /v1/templates`：模板 CRUD，`doc_type` 为键。
- `POST /v1/templates/import`：第三方导入提供模板样式（版式/字体/落款）。

### 5.5 导出下载（我方提供）
`POST /v1/export`
```json
{ "content": "<生成内容或草稿>", "template_id": "tpl-notice-01", "format": "docx" }
```
响应：`{ "download_url": "/v1/export/{file_id}", "file_id": "..." }`。
`GET /v1/export/{file_id}` 下载文件（docx/pdf）。
> 导出前执行敏感词 / 密级校验，受限内容按权限拦截。

### 5.6 配置中心
- `GET /v1/config/sensitive_word`、`GET /v1/config/format_adapter`、`GET /v1/config/model_profile`
- `PUT /v1/config/{category}`：更新对应配置项。

## 6. 密级与权限过滤行为（重点）

1. **必传**：检索/生成的 `context.caller_scope` 与 `context.max_clearance` 缺失 → `400`。
2. **服务端强制**：过滤在数据库 `WHERE` 下推，涉密/越权内容**不进入模型上下文**，不依赖第三方"不问就不给"。
3. **无 scope 的调用方**：仅可见无权限约束的公开（PUBLIC）内容。
4. **审计提示**：存在被过滤结果时，`truncated_by_security=true`，第三方可据此向用户提示"有部分内容因权限不可见"。

## 8. 错误码标准

| code | 含义 | 处理建议 |
|---|---|---|
| 0 | 成功 | — |
| 400 | 参数缺失/非法（如缺 caller_scope/max_clearance） | 检查请求体必填项 |
| 401 | 鉴权失败 | 检查 Bearer Token / mTLS |
| 403 | 越权/超密级 | 不应发生（过滤后为空时返回空而非 403） |
| 404 | 资源不存在 | 检查 ID |
| 409 | external_id 重复 | 改用幂等更新或换 external_id |
| 422 | 文档解析/格式适配失败 | 检查文件格式/适配配置 |
| 429 | 限流 | 退避重试 |
| 500 | 内部错误 | 联系平台方，附 trace_id |
| 503 | 模型后端不可用（算力中心未就绪） | 检查算力中心网关状态 |

## 9. 部署方算力中心 · 标准模型接口（给算力中心开发者）

我方通过 `ModelProvider(StdProvider)` 对接部署方算力中心。部署方须暴露以下
**兼容 OpenAI 风格**的端点（或在其前加一层兼容网关），即可被我方零改代码接入。

### 9.1 Chat Completions（生成）
`POST {base_url}/v1/chat/completions`
```
Body:   { "model":"<name>", "messages":[{"role":"system|user|assistant","content":"..."}],
          "temperature":0.3, "max_tokens":4096, "stream":false }
Resp:   { "choices":[{"message":{"role":"assistant","content":"..."},"finish_reason":"stop"}],
          "usage":{"prompt_tokens":0,"completion_tokens":0} }
```

### 9.2 Embeddings（向量，离线一次性）
`POST {base_url}/v1/embeddings`
```
Body:   { "model":"<name>", "input":["text1","text2"] }
Resp:   { "data":[{"index":0,"embedding":[0.01,...]}], "model":"<name>" }
```
> 维度须与 `embedding_dim`（当前 1024）一致；**维度确定后不可随意更换**（需重建全部向量）。

### 9.3 Rerank（重排，在线，可选）
`POST {base_url}/v1/rerank`
```
Body:   { "model":"<name>", "query":"...", "documents":["...","..."] }
Resp:   { "results":[{"index":0,"score":0.93},{"index":1,"score":0.81}] }
```
> 部署方未提供 rerank 时，我方回退至 RRF 融合分排序。

### 9.4 ModelProfile 配置（在我方配置中心写入）
```json
{
  "name": "客户算力中心-A",
  "provider_type": "std",
  "base_url": "https://gpu-center.internal/v1",
  "api_key": "***",
  "model_name": "self-hosted-qwen3-32b",
  "capabilities": ["chat","embed","rerank"],
  "dims": 1024,
  "enabled": true
}
```
`provider_type ∈ {local, cloud, std}`：`local`=我方默认 Qwen3 栈；`cloud`=开发期云端；`std`=部署方算力中心。

## 12. 常见问题（FAQ）

**Q1：我方是否重认证终端用户？**
不重认证。身份由第三方网关负责；我方只消费网关下发的 `caller_scope` / `max_clearance` 做过滤。

**Q2：涉密内容能否出网？**
不能。涉密信息禁止出网（生产环境网络策略封死出口 + 启动自检拒绝云端 Provider）。

**Q3：更换 Embedding 模型会有什么后果？**
需重建全部向量（20 万文档约 193 万切片）。维度确定后请勿随意更换。

**Q4：过滤是客户端自觉还是需要服务端保证？**
服务端强制（数据库 WHERE 下推）。即使第三方未传 scope，也仅返回无权限约束的公开内容。

**Q5：返回为空是 403 还是正常？**
正常返回空数组（`citations: []`），而非 403；`truncated_by_security` 提示是否存在被过滤项。
