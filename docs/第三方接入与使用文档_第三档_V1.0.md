## 1. 文档目的与边界

### 1.1 目的

本文回答三个问题：

1. **平台提供什么功能**——功能全景清单（第 3 章）；
2. **怎么接入**——按接入深度分三档，第三档（私有化部署级）的完整接入方法（第 4 章）；
3. **接口怎么调**——全部端点的详细接口文档：请求参数（字段/类型/必填/默认/说明）、请求示例、响应字段、响应示例、错误码（第 5–7 章）。

### 1.2 边界

- 本文只覆盖**平台对外开放的能力**；平台内部实现（解析/切分/检索管线）见《详细设计文档 V1.2》《文档入库流程说明》。
- 平台运行于**部署方内网**，不提供公网服务；涉密内容不出网由部署方网络边界与我方启动自检共同保证。
- 平台**不重认证终端用户**：信任上游网关传入的调用方身份（JWT 或 API Key）与调用上下文（`caller_scope` / `max_clearance`）；但密级/权限过滤由平台**服务端强制执行**。

## 2. 接入档位体系

平台按接入深度定义三档，部署方按自身情况选档；**本文完整覆盖第三档**，前两档在此定义以便选型。

| 档位 | 名称 | 接入内容 | 适用场景 | 工作量 |
|---|---|---|---|---|
| 第一档 | 接口联调 | HTTP API 直调：注册客户端 → 接入文档 → 检索/问答 | PoC 验证、联调期 | 小时级 |
| 第二档 | 业务集成 | 在第一档基础上嵌入业务系统：会话管理、模板选用、空间隔离、权限上下文、导出下载 | 生产环境业务集成 | 天级 |
| **第三档** | **私有化部署级接入** | **接管运行环境：基础设施部署、模型接入（算力中心标准接口）、存储选型、权限主数据对接、密级映射、前端嵌入、运维监控** | **政企内网私有化部署** | **周级** |

### 2.1 第三档与其他两档的关系

- 第一/二档解决"**调用**"问题；第三档解决"**落地运行**问题。
- 第三档交付物 = 平台镜像（Docker Compose）+ 部署方提供的四类资源（文档数据、模型、权限主数据、前端）。
- 第三档接入方通常同时是第二档的调用方（自己的业务系统调用平台 API）。

### 2.2 第三档职责边界

| 平台方（我方）提供 | 部署方（第三方）提供 |
|---|---|
| 平台全部代码与镜像（后端 + 运维台前端 + OFD 解析独立库） | 文档数据（按平台字段标准携带密级/权限） |
| 接口规范、字段标准、密级/权限枚举、模型接入标准 | 模型服务（可选自有算力中心，实现标准接口；或用平台本地 Qwen3 栈） |
| 文档解析 / 切片入库 / 检索推理 / 模板库维护 / 导出 / 配置中心 / 运维台 | 组织架构 / 认证 / 权限主数据（映射为 `scope:` 标签） |
| 启动自检（数据库 / 存储 / Embedding / Rerank）与排障提示 | 前端调用（可嵌入运维台，或自建前端调 API） |
| 密级/权限过滤执行（服务端 WHERE 下推）、敏感词配置与应用 | 网络隔离与出口封死（涉密不出网） |

## 4. 第三档接入方法

### 4.1 部署拓扑

```
┌────────────────────────── 部署方内网 ──────────────────────────┐
│                                                               │
│  第三方业务系统 ──HTTPS──► ┌────────── 平台（Docker Compose）┐  │
│  （或嵌入运维台前端）      │ 后端 API（FastAPI，:8000）       │  │
│                           │ 运维台前端（Vue3，:80 反代）     │  │
│                           └──────┬───────────────┬──────────┘  │
│                                  │               │             │
│                    ┌─────────────▼─┐   ┌─────────▼──────────┐  │
│                    │ PostgreSQL    │   │ 对象存储           │  │
│                    │ + pgvector    │   │ LocalFS（默认）/   │  │
│                    │ + zhparser    │   │ S3 兼容            │  │
│                    └───────────────┘   └────────────────────┘  │
│                                                               │
│   ┌──────────────────────┐   ┌──────────────────────────┐     │
│   │ 部署方算力中心（可选）│   │ 权限主数据 / 上游网关     │     │
│   │ Chat/Embed/Rerank    │   │ 下发 JWT 或 API Key +    │     │
│   │ 标准接口（OpenAI 风格）│   │ caller_scope/max_clearance│     │
│   └──────────────────────┘   └──────────────────────────┘     │
└───────────────────────────────────────────────────────────────┘
```

组件清单（最小集）：PostgreSQL 15+（pgvector + zhparser 扩展，镜像已定制）、后端服务、对象存储（LocalFS 零依赖起步，可切 S3 兼容）、模型服务（本地 Qwen3 栈或部署方算力中心）。

### 4.2 网络与安全边界

- 平台仅监听内网；**生产环境（`ENVIRONMENT=production`）启动自检拒绝 cloud 模型 Provider**——涉密不出网的第一道闸。
- 部署方负责网络出口封死（模型/存储/数据库全部内网可达）。
- API Key 服务端仅存 sha256 哈希，明文仅注册时返回一次；客户端可被 admin 即时禁用（止血）。

### 4.3 认证（双模，强制）

| 调用方 | 认证头 | 获取方式 |
|---|---|---|
| 运维台用户 | `Authorization: Bearer <JWT>` | `POST /v1/auth/login`，默认 12 小时有效 |
| 第三方系统（机对机） | `X-API-Key: sk-xxxx` | `POST /v1/auth/clients/register`，**明文仅返回一次** |

- 任一通过即放行（Bearer 优先）；全部 `/v1/*` 业务端点强制认证。
- **开放端点**（无需认证）：`POST /v1/auth/login`、`POST /v1/auth/clients/register`、`GET /health`、`GET /docs`、`GET /redoc`、`GET /openapi.json`。

### 4.4 能力域与密级额度

**能力域（scopes）**：`chat` / `retrieve` / `documents` / `spaces` / `conversations` / `templates` / `config` / `audit` / `ops`，或 `["*"]` 全开。缺失对应域 → `403`。按最小必要原则分配（如只做问答的系统给 `["chat","retrieve","conversations"]`）。

**密级额度（max_clearance）**：见第 6 章六级映射。用户按角色映射（`admin`→机密，其余→内部）；客户端注册时指定。请求体声明的 `max_clearance` **不得超过调用方额度**，超出自动压低（服务端强制）。

### 4.5 调用上下文（检索/生成必带）

- `caller_scope`：调用方权限标签（`scope:<type>:<value>`，`type ∈ {dept, role, user, group}`），由部署方权限主数据映射而来。例：`["scope:dept:总部", "scope:role:公文员"]`。
- `max_clearance`：本次请求的密级上限（被额度压低后生效）。
- 平台按"文档密级权重 ≤ 上限 **且** 权限标签与 caller_scope 有交集（或无标签）"做服务端 WHERE 下推；**过滤后为空返回空列表（非 403）**。

### 4.6 模型接入（部署方算力中心）

平台通过 `ModelProvider(std)` 对接部署方算力中心。算力中心（或其前置网关）暴露三个 **OpenAI 兼容风格**端点：

| 端点 | 用途 | 必需性 |
|---|---|---|
| `POST {base_url}/v1/chat/completions` | 生成（Qwen3-32B 级） | 必需 |
| `POST {base_url}/v1/embeddings` | 向量（入库一次性 + 查询） | 必需 |
| `POST {base_url}/v1/rerank` | 重排 | 可选（缺失则回退 RRF 融合分排序） |

请求/响应格式见 5.13 节。接入方式：在配置中心写 `model_profile`（5.10 节），`provider_type="std"`，保存即时生效，无需重启。平台默认栈为本地 Qwen3（Embedding-4B / Reranker-0.6B / 生成 32B-INT4），`provider_type ∈ {local, cloud, std}`。

### 4.7 存储接入

- **默认 LocalFS**：文件落服务器磁盘，零额外组件，适合单机部署。
- **S3 兼容**（SeaweedFS / Ceph RGW / 国产对象存储）：配置 `STORAGE_PROVIDER=s3` + endpoint/ak/sk/bucket，经 boto3 接入；两种模式对 API 完全透明（`content_ref` 语义一致）。
- 存储内容：上传原文（按 `raw/{doc_id}.{ext}`）、模板原件。

### 4.8 权限主数据对接

1. 部署方在其权限系统维护组织架构（部门/角色/用户/用户组）；
2. 接入文档时把权限对象写为 `permission_tags`（平台标准格式 `scope:type:value`）；
3. 上游网关在每次请求下发调用方的 `caller_scope`（该用户可见的标签集合）；
4. 平台在检索/问答/生成/导出全链路执行交集判定。

> 平台不存储也不解析部署方的组织架构，只认标准标签——权限主数据的维护成本留在部署方侧，平台保持无状态。

### 4.9 前端嵌入（两种方式）

1. **直接用运维台**：平台自带 Vue3 运维台（文档库/检索/问答/起草/模板/配置/运维监控七个视图），部署后即可用；
2. **嵌入自建前端**：自建页面调平台 API（第二档能力），或把运维台作为静态资源嵌入门户 iframe。文档库上传弹窗已支持 PDF/DOCX/OFD/TXT 四种格式选择。

## 5. 详细接口文档

### 5.1 通用约定

| 项 | 约定 |
|---|---|
| Base | `https://<部署域内网>/v1/` |
| 协议 | HTTPS（内网）；UTF-8；时间 ISO-8601（`2025-10-13T08:30:00+00:00`） |
| 认证 | `Authorization: Bearer <JWT>` 或 `X-API-Key: sk-xxxx`（双模，见 4.3） |
| 成功响应 | 直接返回该端点响应 Model JSON（无外层包装） |
| 失败响应 | `{"detail": "<错误描述>"}` + HTTP 状态码（见第 7 章） |
| 流式（SSE） | `Content-Type: text/event-stream`，事件为 `data: {json}\n\n` |
| 文件下载 | 直接返回文件流（`Content-Disposition: attachment`） |

---

### 5.2 认证接口（/v1/auth）

#### 5.2.1 用户登录（换 JWT）

`POST /v1/auth/login` — **开放端点**

**请求体：**
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| username | string | 是 | 用户名 |
| password | string | 是 | 口令（pbkdf2-sha256 26 万迭代校验，恒定时间比较） |

**响应（HTTP 200）：**
| 字段 | 类型 | 说明 |
|---|---|---|
| access_token | string | JWT（HS256，payload：sub/username/role/iat/exp） |
| token_type | string | 固定 `"bearer"` |
| expires_in | int | 有效期（秒，默认 43200 = 12h） |
| user | object | `{ id, username, display_name, role, enabled, last_login_at }` |

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "token_type": "bearer",
  "expires_in": 43200,
  "user": { "id": "u-001", "username": "admin", "display_name": "系统管理员",
            "role": "admin", "enabled": true, "last_login_at": "2026-10-13T08:30:00+00:00" }
}
```

> 失败：`401 {"detail":"用户名或口令错误"}`（不区分账号不存在与口令错误，防枚举）。

#### 5.2.2 当前登录用户

`GET /v1/auth/me` — 需 `Authorization: Bearer <JWT>`

**响应（HTTP 200）：** UserResp：`{ id, username, display_name, role, enabled, last_login_at }`。`401` 表示未登录/令牌过期。

#### 5.2.3 第三方客户端注册（返回一次性 API Key）

`POST /v1/auth/clients/register` — **开放端点**

**请求体：**
| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| name | string | 是 | — | 客户端名称（建议接入系统名，便于审计） |
| scopes | string[] | 否 | `["chat","retrieve"]` | 能力域白名单（见 4.4） |
| max_clearance | enum | 否 | `INTERNAL` | 密级额度（六级，见第 6 章） |

**响应（HTTP 200）：**
| 字段 | 类型 | 说明 |
|---|---|---|
| client_id | string | 客户端 ID（`cli-` 前缀） |
| name | string | 客户端名称 |
| key_prefix | string | API Key 前缀（如 `sk-Ab3xK9...`），仅供核对 |
| scopes | string[] | 生效的能力域 |
| max_clearance | string | 密级额度 |
| enabled | bool | 是否启用 |
| expires_at | datetime \| null | 过期时间（当前版本恒为 null = 不过期） |
| created_by | string | 创建者（自助注册为 `self-register`） |
| last_used_at / created_at | datetime \| null | 最近使用 / 创建时间 |
| **api_key** | string | **API Key 明文，仅此一次返回，请立即保存** |

```json
{
  "client_id": "cli-9f2c1a0b3d4e5f60", "name": "OA 公文系统",
  "key_prefix": "sk-Ab3xK9...", "scopes": ["chat", "retrieve"],
  "max_clearance": "INTERNAL", "enabled": true, "expires_at": null,
  "created_by": "self-register", "last_used_at": null,
  "created_at": "2026-10-13T09:00:00+00:00",
  "api_key": "sk-XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX"
}
```

> 注册成功后，业务调用只需带 `X-API-Key: sk-XXX`。

#### 5.2.4 客户端列表 / 禁用 / 启用（admin）

- `GET /v1/auth/clients` — 需 **admin 用户 JWT**。响应 `ClientResp[]`（字段同注册响应，但**永不含 api_key 明文**）。
- `POST /v1/auth/clients/{client_id}/disable` / `POST /v1/auth/clients/{client_id}/enable` — 需 **admin 用户 JWT**。响应更新后的 ClientResp。
  > 禁用后该客户端持有的 API Key **立即失效**（应急止血）；`404` 表示客户端不存在。

### 5.3 文档空间（/v1/spaces）

> 文档空间是知识库的逻辑分区（支持层级，类似文件夹）。文档归属空间，检索/问答可按 `space_ids` 限定范围。默认空间固定 ID `spcdefault0000000000000000000000`（system 公共空间：所有人可见、可上传）。
>
> **所有权规则**：第三方/用户创建的空间**仅创建者本人可见、可上传、可检索**；他人空间列表/详情不可见（`404`，不暴露存在性）、上传 `403`、纳入检索 `403`；空间 owner 由服务端按调用方身份写入，**不接受客户端指定**。

#### 5.3.1 创建空间

`POST /v1/spaces` — 需认证（scopes 含 `spaces` 或 `*`）

**请求体：**
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| name | string | 是 | 空间名称（1–128 字符） |
| code | string | 是 | 空间编码（唯一，第三方稳定标识，1–64 字符） |
| description | string | 否 | 描述（≤512 字符） |
| parent_id | string \| null | 否 | 父空间 ID；缺省为根级（须为默认空间或本人空间） |

**响应（HTTP 201，SpaceResp）：** `{ id, name, code, description, is_default, parent_id, owner_type, owner_id, owner_name, is_mine, can_upload, doc_count, chunk_count, created_at, updated_at }`

> `409` 空间编码已存在 / 父空间不存在（`404`）/ 无权在他人空间下建子空间（`403`）。

#### 5.3.2 列表 / 详情 / 更新 / 删除

- `GET /v1/spaces` → `SpaceResp[]`（默认空间置顶，含实时统计；**仅返回默认空间 + 本人创建的空间**）。
- `GET /v1/spaces/{space_id}` → `SpaceResp`（不存在或非本人空间均 `404`）。
- `PUT /v1/spaces/{space_id}` — 请求体均选填：`name`（1–128）、`description`（≤512）、`parent_id`（null 表示移到根级）。响应 `SpaceResp`。
  > 仅创建者可更新（`403`）；默认空间仅 admin 可改名、不支持移动（`409`）；防环校验：不能移动到自己的下级或子孙节点下（`409`）。
- `DELETE /v1/spaces/{space_id}` → `{"deleted": "<space_id>"}`。
  > 保护策略（均 `409`）：默认空间不可删；空间内仍有文档不可删；下仍有子空间不可删。

#### 5.4.1 单篇接入（内联正文）

**请求体（DocumentIngest）：**
| 字段 | 类型 | 必填 | 默认 | 说明 |

| external_id | string | 是 | — | 第三方主键（**幂等键**，重复接入不重复入库） |

| doc_no | string | 否 | null | 文号 |

|---|---|---|

| message | string | 附加说明 |

```json
  "doc_no": "X农发〔2026〕12号",
  "publish_date": "2026-03-01",
  "security_level": "INTERNAL",
  "permission_tags": ["scope:dept:总部", "scope:role:公文员"],
  "space_id": "spcdefault0000000000000000000000",
  "content": "各市（州）农业（农牧）局：\n\n为做好2026年春季农业生产工作，现将有关事项通知如下：\n\n一、…"
}
```

#### 5.4.2 文件上传接入（PDF / DOCX / OFD / TXT，异步）

`POST /v1/documents/upload` — 需认证；`multipart/form-data`

**表单字段：**
| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| file | file | —（必填） | PDF / DOCX(.doc) / **OFD** / TXT(.md) 文件。无扩展名的第三方导出文件按文件头嗅探（PK 魔数会解包区分 OFD 与 DOCX，不会误判） |
| external_id | string | 文件名 | 第三方主键 |
| title | string | 文件名 | 标题 |
| doc_type | string | `通知` | 文种 |
| issuer / doc_no / publish_date | string | 空 | 元数据 |
| security_level | enum | `INTERNAL` | 密级 |
| permission_tags | string | 空 | 逗号分隔，如 `scope:dept:总部,scope:role:公文员` |
| space_id | string | 空 | 目标空间；缺省归入默认空间。**仅限默认公共空间或本人创建空间**（他人空间 `403`） |
| chunk_strategy | enum | `paragraph` | 切分策略 |
| chunk_size / chunk_overlap | int | 800 / 80 | 切片参数 |

**响应（HTTP 200，IngestionJobResp）：** 入库任务（状态机进度，前端轮询 5.4.4）：
`{ id, filename, status, progress, total_chunks, processed_chunks, error_message, document_id, strategy, chunk_size, chunk_overlap, security_level, doc_type, created_at, updated_at }`

**任务状态机：** `PENDING → PARSING → CHUNKING → EMBEDDING → INDEXED`，任意阶段异常 → `FAILED`（`error_message` 带原因）。

**重复上传处理（2026-10-15 起）**：`external_id` 已存在时任务直接置 `INDEXED`，`document_id` 关联已有文档，`error_message` 为可读提示（"文档已存在…已跳过重复入库"），**不会**重复切分/向量化。

> **任务所有权**：入库任务按提交者隔离——`GET /v1/documents/jobs` 仅返回本人任务；他人任务 ID 查询返回 `404`。

#### 5.4.3 文档库列表（管理视图）

`GET /v1/documents` — 需认证

**Query 参数（均选填）：**
| 参数 | 类型 | 默认 | 说明 |

| doc_type | string | — | 按文种过滤 |
| security_level | string | — | 按密级过滤（六级枚举值） |
| space_id | string | — | 按文档空间过滤 |
| status | string | — | 按状态过滤 |
| q | string | — | 标题/文号模糊检索 |
| page | int | 1 | 页码（≥1） |
| size | int | 20 | 每页条数（1–200） |

**响应（DocumentSummary[]）：** `{ id, external_id, title, doc_type, issuer, doc_no, security_level, permission_tags, space_id, space_name, status, chunk_count, created_at }`

> **空间所有权**：列表/统计/详情仅覆盖本人可见空间内的文档（默认公共 + 本人创建）；他人空间文档不可见（详情 `404`）。

#### 5.4.4 统计 / 入库任务 / 详情

- `GET /v1/documents/stats?space_id=<可选>` → **DocStats**：`{ total_documents, total_chunks, by_status: {状态:数量}, by_security: {密级:数量} }`（仅统计本人可见空间）。

### 5.5 检索（/v1/retrieve）

`POST /v1/retrieve` — 需认证（scopes 含 `retrieve` 或 `*`）

**请求体（RetrieveRequest）：**
| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| query | string | 是 | — | 检索问题 |
| doc_types | string[] | 否 | null | 限定文种 |
| space_ids | string[] | 否 | null | 限定文档空间（多选）；**仅可纳入本人可见空间**，他人空间 `403` |
| top_n | int | 否 | 8 | 返回条数 |
| caller_scope | string[] | 否 | [] | 调用方权限标签（见 4.5） |
| max_clearance | enum | 否 | `INTERNAL` | 请求密级上限（服务端按调用方额度压低） |
| rerank | bool | 否 | true | 是否启用重排（服务不可用自动降级 RRF） |

**响应（HTTP 200，RetrieveResp）：**
| 字段 | 类型 | 说明 |
|---|---|---|
| query | string | 回显检索问题 |
| citations | Citation[] | 命中列表（**已做密级/权限下推过滤**） |
| total_matched | int | 命中总数 |
| truncated_by_security | bool | 是否存在因密级/权限被过滤的结果 |
| top_vector_distance | float \| null | 向量路 top1 余弦距离（"无有用信息"判定信号） |
| keyword_hits | int | 关键词路命中数 |

**Citation Model：** `{ chunk_id, document_id, title, doc_no, snippet, score, content, granularity }`
（`content` 仅条件父块注入的大块携带完整正文；`granularity` = `small` 检索块 / `large` 生成块。）

```json
{
  "query": "安全生产责任追究",
  "citations": [
    { "chunk_id": "c-123", "document_id": "d-1", "title": "关于...的通知",
      "doc_no": "XX函〔2025〕12号", "snippet": "...", "score": 0.91,
      "content": null, "granularity": "small" }
  ],
  "total_matched": 3, "truncated_by_security": false,
  "top_vector_distance": 0.31, "keyword_hits": 3
}
```

> 密级/权限过滤在检索阶段服务端 WHERE 下推；过滤后为空返回空列表（非 403）。

### 5.7 会话（/v1/conversations）

> 智能问答（chat）与公文起草（draft）共用会话体系；多轮上下文由后端在生成时自动拼接（历史轮次截断 2000 字/条注入）。

- `POST /v1/conversations` — 需认证。**请求体：** `conv_type`（`chat`/`draft`，默认 `chat`）、`title`（≤256）、`space_ids`（绑定的知识空间，**仅限本人可见空间**，他人空间 `403`）。**响应：** `ConversationResp`（HTTP 201）。
- `GET /v1/conversations` — 会话列表（按最后活跃倒序）。

  **历史搜索（2026-10-15 起，Query 参数均选填，可与 `conv_type` 组合）：**
  | 参数 | 类型 | 说明 |
  |---|---|---|
  | `keyword` | string | 关键字模糊搜索：标题 ILIKE + 消息内容 EXISTS 子查询（通配符 `%_\` 已转义）；整串恰好等于会话 ID 时也命中。命中消息内容的会话附返 `match_snippet`（命中片段，供前端高亮） |
  | `id` | string | 按会话 ID **精确查找**；不存在返回 `404 {"detail":"会话不存在：<id>"}`（与关键字无匹配返回空列表区分） |
  | `limit` | int | 返回条数（默认 50，1–200） |

  **请求示例：**
  ```bash
  # 关键字搜索（标题 + 消息内容）
  GET /v1/conversations?conv_type=chat&keyword=退役准备
  # 明确 ID 精确查找
  GET /v1/conversations?id=8f3a2b1c9d4e5f60718293a4b5c6d7e8
  ```
- `GET /v1/conversations/{id}` → **ConversationDetail**（ConversationResp + `messages`：MessageResp[]）。`404` 不存在。
- `PUT /v1/conversations/{id}` — **请求体：** `title`、`space_ids`（均选填；新绑定空间同样限本人可见，`403`）。**响应：** `ConversationResp`。
- `DELETE /v1/conversations/{id}` → `{"deleted": "<id>"}`（消息级联删除）。
- `POST /v1/conversations/{id}/messages` — 手动追加消息（停止生成补存等场景）。**请求体：** `role`（`user`/`assistant`，默认 `assistant`）、`content`（必填）、`citations[]`、`sensitive_hits[]`、`model`、`intent`、`reasoning`。**响应：** `MessageResp`（HTTP 201）。

**ConversationResp Model：** `{ id, title, conv_type, doc_type, space_ids, message_count, last_message_at, created_at, updated_at, match_snippet }`
**MessageResp Model：** `{ id, role, content, citations, sensitive_hits, model, intent, reasoning, created_at }`
（`reasoning` = 模型思考链全文；`intent` = Agent 意图标识留痕；`doc_type` = 起草会话绑定的文种；`match_snippet` = 仅关键字搜索命中消息内容时返回。）

### 5.8 模板库（/v1/templates）

> 平台维护 8 类标准公文模板（开箱即用）；同一文种支持配置多个模板（起草时用 `template_code` 精确选用，见 5.6.1）。
> **所有权隔离**：系统标准模板所有人可见、可引用起草，仅 admin 可维护；用户/第三方上传的模板仅创建者本人可见、可编辑、可删除，他人不可见、引用其 code 起草时 `403`。

- `GET /v1/templates` — 需认证。**响应：** `ConfigItem[]`，每项 `{ category:"template", key:<模板编码 code>, value:{ doc_type, name, layout, content_ref, owner_type, owner_id, owner_name, is_mine, can_edit } }`。
  **layout 结构：** `{ red_head: bool, font: string, paper: string, subtitle: string, tone: string, sections: [{key, label, placeholder, required}] }`（导出 DOCX 时按 `font`/`red_head` 应用版式，见 5.9）。
- `POST /v1/templates` — 需认证。**请求体（ConfigItem）：** `category="template"`、`key=<模板编码 code>`、`value={doc_type, name, layout}`。**响应：** 创建或更新后的 ConfigItem（code 已存在则更新其版式）。更新他人模板或系统标准模板 → `403`。
- `POST /v1/templates/upload` — 需认证；`multipart/form-data`：`file`（**docx/pdf/ofd/txt**）、`doc_type`（可空，自动识别）、`name`。每次上传作为**独立新模板**（自动生成 code，不覆盖同文种已有模板），**归属上传方**。**响应：** ConfigItem。
- `GET /v1/templates/{code}/file` — 需认证。下载该模板的上传原件（文件流；无上传文件时 `404`；他人模板不可见 → `404`）。
- `POST /v1/templates/seed` — 需认证，**限 admin**。手动初始化标准模板库（幂等，不覆盖已有模板）→ `{"added": int, "message": string}`。
- `DELETE /v1/templates/{code}` — 需认证 → `{"deleted": bool}`。仅创建者可删除本人模板；系统标准模板限 admin；他人模板 → `403`。

### 5.9 导出下载（/v1/export）

`POST /v1/export/docx` — 需认证（scopes 含 `chat` 或 `*`）

**请求体（ExportDocxRequest）：**
| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| conversation_id | string | 是 | — | 会话 ID（定位已生成的起草内容） |
| message_id | string | 否 | null | 精确指定某一轮 assistant 消息；缺省取会话内最新一条 assistant 消息 |
| template_code | string | 否 | null | 版式模板 code（可选）；模板 `layout` 可覆盖正文字体/红头样式，仅创建者与系统标准模板可用（他人模板 `403`） |

**行为：** 导出【已生成并存库】的内容——按会话 + 消息精确定位某一轮起草的 assistant 正文，**不重新检索/生成**。导出前执行：敏感词二次脱敏（词表可能生成后更新）+ 所引文档密级复核（超出调用方额度 `403`）。

**响应：** docx 文件流（`Content-Disposition: attachment; filename*=UTF-8''<标题>.docx`）。

**版式（GB/T 9704 公文标准）：**
| 元素 | 字体 | 字号 | 版式 |
|---|---|---|---|
| 标题（题名） | 方正小标宋简体 | 二号 22pt | 居中；红头模板描红 |
| 一级标题 | 黑体 | 三号 16pt | 无缩进，段前距 |

### 5.10 配置接口（/v1/config）

> 配置中心按 category/key/value 存储（敏感词、格式适配器、模型 Profile、检索参数、提示词模板等）。所有配置**保存即时生效**，无需重启；服务端每次请求实时读取，缺项/停用/解析异常一律回退代码默认值。

- `GET /v1/config/items?category=<分类>` — 需认证 → `ConfigItem[]`。
  **ConfigItem Model：** `{ category, key, value: object, scope, is_active }`
- `PUT /v1/config/items` — 需认证。**请求体：** ConfigItem（按 category+key upsert）。**响应：** 保存后的 ConfigItem。
- `DELETE /v1/config/items?category=<分类>&key=<键>` — 需认证 → `{"deleted": bool, "category": "...", "key": "..."}`。

**标准分类（category）一览：**
| category | 内容 | 典型 key |
|---|---|---|
| `sensitive_word` | 敏感词词条（命中自动脱敏） | 词条本身，value=`{severity, note}` |
| `format_adapter` | 文件格式适配器 | 名称，value=`{extensions[], priority}` |
| `model_profile` | 模型接入档案 | 名称，value=`{name, provider_type, base_url, api_key, model_name, capabilities[], dims, enabled}` |
| `dict_custom` | 自定义词典（术语标准化映射） | 词条，value=`{mapping}` |
| `agent` | Agent 运行参数 | `enabled`/`llm_classify`/`llm_classify_timeout_ms`/`max_steps`，value=`{value}` |
| `retrieval` | 检索参数（19 项种子） | `final_top_n`/`vector_top_n`/`keyword_top_n`/`rerank_enabled`/`vec_distance_threshold`/`rerank_min_score`/`dual_granularity_enabled`/`small_max_tokens`/`small_overlap_tokens`/`large_max_tokens`/`large_overlap_tokens`/`parent_inject_enabled`/`parent_inject_max_count`/`parent_inject_max_tokens`/`parent_inject_min_rerank`/`rewrite_enabled`/`rewrite_strategy`/`rewrite_max_rounds`/`rewrite_timeout_ms`/`parse_noise_clean`/`chunk_paragraph_rebuild`，value=`{value}` |
| `prompt` | 生成提示词模板 | `draft_system`/`no_materials_system`/`chat_system`/`chat_no_materials_system`，value=`{value: 模板文本}` |

> `retrieval` 类由启动种子写入默认值（幂等，不覆盖用户已改值）；`prompt` 类不种子，未配置时用代码内置文案。

**模型 Profile 写入示例（接入部署方算力中心）：**
```json
{
  "category": "model_profile", "key": "客户算力中心-A",
  "value": {
    "name": "客户算力中心-A", "provider_type": "std",
    "base_url": "https://gpu-center.internal/v1", "api_key": "***",
    "model_name": "self-hosted-qwen3-32b",
    "capabilities": ["chat", "embed", "rerank"], "dims": 1024, "enabled": true
  }
}
```
`provider_type ∈ {local, cloud, std}`：`local` = 平台默认 Qwen3 栈；`cloud` = 开发期云端（生产启动自检拒绝）；`std` = 部署方算力中心（标准接口）。

### 5.13 标准模型接入接口（部署方算力中心须实现）

> 平台通过 `ModelProvider(std)` 对接。部署方算力中心暴露以下标准端点（兼容 OpenAI 风格），或在其前加兼容网关；无需改平台代码即可接入自有模型。

#### 5.13.1 Chat Completions（生成，必需）

`POST {base_url}/v1/chat/completions`
```
Headers: Authorization: Bearer <token>, Content-Type: application/json
Body:   { "model": "<name>", "messages": [{"role":"system|user|assistant","content":"..."}],
          "temperature": 0.3, "max_tokens": 4096, "stream": false }
Resp:   { "choices": [{"message":{"role":"assistant","content":"..."},"finish_reason":"stop"}],
          "usage": {"prompt_tokens":0,"completion_tokens":0} }
```

#### 5.13.2 Embeddings（向量，必需）

`POST {base_url}/v1/embeddings`
```
Body:   { "model": "<name>", "input": ["text1","text2"] }
Resp:   { "data": [{"index":0,"embedding":[0.01,...]}], "model":"<name>" }
```

#### 5.13.3 Rerank（重排，可选）

`POST {base_url}/v1/rerank`
```
Body:   { "model":"<name>", "query":"...", "documents":["...","..."] }
Resp:   { "results": [{"index":0,"score":0.93}, {"index":1,"score":0.81}] }
```
> 部署方若未提供 rerank，平台回退至 RRF 融合分排序。

#### 5.13.4 ModelProfile 配置

在平台配置中心写入（见 5.10 节示例），`provider_type="std"`，保存即时生效。

## 6. 密级与权限过滤行为（重点）

### 6.1 六级密级映射（平台标准，2026-10-15 起）

| 枚举值 | 中文名 | 权重 | 定位 |
|---|---|---|---|
| `PUBLIC` | 非密 | 1.0 | 可对外公开 |
| `INTERNAL` | 内部 | 2.0 | 内部资料（默认） |
| `COMMERCIAL` | 普通商密 | 2.3 | 一般商业秘密 |
| `CORE_COMMERCIAL` | 核心商密 | 2.7 | 核心商业秘密 |
| `CLASSIFIED` | 密级 | 3.0 | 受控密级资料 |
| `TOP_SECRET` | 机密 | 4.0 | 最高密级 |

权重全序：`1.0 < 2.0 < 2.3 < 2.7 < 3.0 < 4.0`（仅用于服务端可见性比较）。

**兼容规则**（存量接入零改造）：
- 历史四级代码自动归一：`RESTRICTED` → `COMMERCIAL`、`SECRET` → `TOP_SECRET`；
- 中文名直传自动归一：`非密`/`内部`/`普通商密`/`商密`/`核心商密`/`密级`/`机密`；
- 存量数据库由启动迁移自动转换（序位一致，可见性关系不变）。

### 6.2 可见性判定（服务端强制）

文档/切片可见 ⇔ **同时**满足：

1. **密级条件**：`security_level` 权重 ≤ 调用方 `max_clearance` 权重；
2. **权限条件**：`permission_tags` 与调用方 `caller_scope` 存在交集；或文档无任何权限标签（全局公开，仅受密级约束）；调用方无 scope 时仅可见无权限约束的内容。

过滤在**检索阶段服务端 WHERE 下推**——涉密/越权内容在数据库层即被排除，**不进入模型上下文**；不是生成后过滤。过滤后为空返回空列表（非 403）。导出口岸同样复核（所引文档密级超额 → `403`）。

### 6.3 典型配置示例

| 场景 | 配置 |
|---|---|
| 只读公开知识的问答机器人 | scopes=`["chat","retrieve","conversations"]`，max_clearance=`PUBLIC` |
| 全量知识库的公文起草 | scopes=`["*"]`，max_clearance=`CORE_COMMERCIAL` |
| 含涉密文件的知识管家 | scopes=`["*"]`，max_clearance=`TOP_SECRET`（对应 admin 用户） |

## 7. 错误码标准

> 错误响应体统一为 `{"detail": "<描述>"}`；业务成功码 200（创建类 201）。

| HTTP | 含义 | 典型 detail |
|---|---|---|
| 200 | 成功 | — |
| 201 | 创建成功 | — |
| 400 | 参数缺失/非法 | 字段校验失败（Pydantic 详情）/ `指定的消息不存在或非起草正文` |
| 401 | 鉴权失败 | `需要登录凭证（Bearer JWT）或 API Key（X-API-Key）` / `用户名或口令错误` / `API Key 无效或已禁用` / `API Key 已过期` / `未登录或登录已过期` |
| 403 | 越权 | `该客户端无 <域> 能力域权限` / `需要管理员权限` / `无权使用该模板（仅创建者与系统标准模板可用）` / `导出内容含超出您密级额度的引用，已拒绝导出` |
| 404 | 资源不存在 | `文档不存在` / `会话不存在` / `会话不存在：<id>` / `客户端不存在` / `文档空间不存在：<id>` |
| 409 | 冲突 | `external_id 重复` / `空间编码已存在：<code>` / `默认空间不可删除` / `空间内仍有 N 篇文档…` / `不能把空间移动到自己的子孙节点下` |
| 422 | 解析/格式失败 | 文档解析或格式适配失败 |
| 429 | 限流 | — |
| 500 | 内部错误 | — |
| 503 | 模型后端不可用 | 算力中心未就绪 |

## 8. 集成时序

### 8.1 最小联调链路（30 分钟）

1. `GET /health` 确认服务就绪；
2. `POST /v1/auth/clients/register` → 保存 `api_key`（一次性）；
3. `POST /v1/documents/ingest`（带 `X-API-Key`）接入一篇文档；
4. `POST /v1/retrieve` 验证检索命中；
5. `POST /v1/chat/stream` 验证问答（SSE）；
6. `POST /v1/export/docx` 验证公文版式导出。

### 8.2 生产集成链路（第三档）

1. 基础设施：拉起 PostgreSQL（pgvector+zhparser）+ 存储（LocalFS/S3）+ 模型（本地栈或算力中心标准接口）；
2. 启动自检四项全绿（db/storage/embedding/rerank）；
3. 配置中心：写 `model_profile`（std 接入）、检索参数、敏感词、提示词模板；
4. 权限主数据：部署方把组织架构映射为 `scope:` 标签；上游网关下发 JWT/API Key + `caller_scope`/`max_clearance`；
5. 文档批量接入（`/ingest` 幂等或 `/upload` 异步），轮询任务状态至 `INDEXED`；
6. 业务系统调用检索/问答/起草/导出；历史用 `/conversations?keyword=` 检索；
7. 运维：`/v1/audit/logs` 留痕审计，`/health` 与运维台监控。

## 10. 常见问题（FAQ）

**Q1：上传返回 200 但文档搜不到？**
上传是异步入库：轮询 `/v1/documents/jobs/{job_id}` 至 `INDEXED` 才算完成（`FAILED` 看 `error_message`，常见为解析失败）。

**Q2：检索结果为空但确认库里有文档？**
依次排查：① `space_ids` 是否限定了非本人空间（403 或空）；② `caller_scope` 与文档 `permission_tags` 无交集；③ `max_clearance` 低于文档密级（`truncated_by_security=true` 即此因）。过滤后为空返回空列表而非 403。

**Q3：历史会话太多，如何定位某一轮？**
`GET /v1/conversations?keyword=<关键字>`（标题+消息内容模糊搜，命中消息返回高亮片段），或 `GET /v1/conversations?id=<完整会话ID>` 精确直达。

**Q4：导出的 docx 能带模板版式吗？**
可以：`template_code` 指定模板，其 `layout.font`（正文字体）/`red_head`（红头）会应用到导出；系统标准模板与本人创建的模板可用。

**Q5：重复接入同一篇文档会怎样？**
`/ingest` 返回 `status="duplicate"`（不重复入库）；`/upload` 重复 `external_id` 直接置 `INDEXED` 并关联已有文档（跳过切分/向量化）。

**Q6：想用自己的模型？**
在配置中心写 `model_profile`（`provider_type="std"`，指向算力中心），实现 5.13 三个标准端点即可；缺 rerank 自动回退 RRF，不影响主链路。

**Q7：旧系统按四级密级（RESTRICTED/SECRET）传参，升级后会 422 吗？**
不会。服务端自动归一（RESTRICTED→普通商密、SECRET→机密），存量接入零改造；数据库存量行由启动迁移自动转换。
