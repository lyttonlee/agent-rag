## 1. 现状问题与实测证据

对 30 篇四川省政府公报 PDF（`sichuan_gov_docs/`）全量实测，发现三辆"重卡"级问题，全部有数据支撑：

### 问题 1：版式噪音（页码/页眉）混入正文

多页公文每页页脚为 `—\n１\n—` 三行（破折线包裹的全角页码），逐页提取后原样拼入正文：

```
--- p2 (25 lines) tail: ['—', '２', '—']
--- p3 (25 lines) tail: ['—', '３', '—']
```

后果：① 正文出现 `……推动融合发展— ４ —五、改善服务基础条件` 这类断裂；② 页码进入 embedding 与 BM25 索引，污染检索；③ 页间拼接产生**假段落边界**（跨页同一段落被 `\n` 截断），直接导致切分在段中下手（见问题 3）。

### 问题 2：方正书版系 PDF 的标点映射乱码（全语料 4,300+ 处）

该类 PDF 的字体 ToUnicode 表把中文标点映射到了错误 Unicode 区段，PyMuPDF 如实吐出乱码字符：

| 错误码点 | 字符 | 出现次数 | 实测上下文 | 应为 |
|---|---|---|---|---|
| U+0A3AC | `ꎬ` | 2597 | `人民政府ꎬ省政府各` | `，` |
| U+0A3AE | `ꎮ` | 1595 | `万户以上ꎮ到２０３０` | `。` |
| U+0A3BB | `ꎻ` | 124 | `００万亩次ꎻ服务主体` | `；` |
| U+1001B0 | `𐆰` | 6 | `全省ＰＭ２𐆰５平均浓度` | `.` |
| U+100170 | `𐆵` | 6 | `创投天府𐆵周周见` | `·` |
| U+1003D1 | `𐏑` | 4 | `按８𐏑２比例负担` | `:` |

后果：① **句子边界识别全面失效**——`。` 全部变成 `ꎮ`，句切分/软切分/段落重组全部失去锚点；② 生成的答案与引用会带出乱码标点；③ BM25 分词把 `ꎬ` 当生僻字，破坏关键词命中。

### 问题 3：小 chunk 从正文中间切断（违背"段落优先"预期）

旧 `paragraph` 策略的单元提取正则 `_SPLIT_RE` 含 `(?<=[。！？；])\s*`——**在句末标点后强制切分**，所谓"段落策略"实际单元是"句子"：

1. 一个 300 token 的小块 = 约 4-6 个句子，可跨 2-3 个自然段，段落边界被无视；
2. 长段落（超过 300 token）被 `_soft_windows` 按句打包切断，段不再完整；
3. 叠加问题 1 的页间假边界，切断点完全不可预测。

用户诉求明确：**小 chunk 必须保证段落完整性（默认 paragraph 切分）**。

## 2. 重构后的全链路流程

```
原始字节 (filename + bytes)
      │
      ▼
┌─────────────────────────────────────────────────────┐
│ 阶段 1  格式识别 sniff                                │
│   magic bytes（%PDF / PK）+ 扩展名；PK 包解包判 OFD    │
└─────────────────────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────────────────────┐
│ 阶段 2  格式解析 parse（位置感知，产出"物理行"序列）     │
│   PDF  : PyMuPDF dict 模式，逐页取行 + bbox            │
│   DOCX : python-docx 按 body 顺序迭代 w:p / w:tbl     │
│   OFD  : ofdkit 独立库（ZIP 导航 + 坐标阅读顺序）       │
│   TXT  : 直读（UTF-8/GBK/BOM）                        │
└─────────────────────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────────────────────┐
│ 阶段 3  清洗 normalize（新增，配置开关默认开）          │
│   3a 乱码码点规范化：映射表 + 可疑区段扫描告警           │
│   3b 页码/页眉页脚剔除：位置区（上8%/下8%）+ 页码模式    │
│      + 跨页高频重复行（≥50% 页同文本同区域）            │
│   3c 空白规范化：全角数字字母半角化、行尾空格、连续空行  │
└─────────────────────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────────────────────┐
│ 阶段 4  段落重建 paragraphing（新增，配置开关默认开）   │
│   软换行合并（PDF/OFD 一行≠一段）+ 标题行强制分段        │
│   + 括号跨行合并 + 空行分段 → 自然段序列               │
└─────────────────────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────────────────────┐
│ 阶段 5  切分 chunking（重写：段落优先）                 │
│   单元 = 自然段；段内不切                               │
│   段落超预算 → 句边界软切 → 单句超预算 → 子句边界切      │
│   → token 窗口硬切（四级降级，逐级保完整）               │
│   双粒度 small/large 独立切分 + 父子挂载                │
└─────────────────────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────────────────────┐
│ 阶段 6  向量化 + 落库（不变：仅 small embed，large 纯文本）│
└─────────────────────────────────────────────────────┘
```

**阶段间契约**：阶段 2-4 全部产出"带行结构的纯文本"（`\n` 分隔物理行/自然段），阶段 5 只依赖 `\n` 边界，不感知来源格式——格式差异在阶段 2 前消化掉，切分器保持格式无关。

## 3. 详细实现方案

### 3.1 阶段 3a：乱码码点规范化（新模块 `services/textnorm.py`）

```python
# 方正书版系 PDF 的 ToUnicode 错位映射（30 篇语料全量实测，上下文逐一人工核对）
FONT_GLYPH_FIXES: dict[str, str] = {
    "\u0a3ac": "，",   # 逗号（2597 处）
    "\u0a3ae": "。",   # 句号（1595 处）
    "\u0a3bb": "；",   # 分号（124 处）
    "\U001001b0": ".", # 英文点（PM2.5 等）
    "\U00100170": "·", # 间隔号（创投天府·周周见）
    "\U001003d1": ":", # 冒号（8:2 比例）
}
SUSPECT_RANGES = (0xA000, 0xA8FF), (0xE000, 0xF8FF), (0x100000, 0x1003FF)
```

规则：
1. 命中映射表 → 替换为正确字符；
2. 落在可疑区段但**未命中映射表** → 不静默丢弃，保留原字符并 `logger.warning` 计数（运维可在日志发现新变体，扩充映射表）；
3. 顺带做：NFC 规范化、零宽字符（U+200B/U+FEFF/U+2060）剔除、全角数字字母→半角（检索友好：`２０２５`→`2025`；中文标点保持全角，保公文原貌）。

### 3.2 阶段 3b：页码/页眉页脚剔除（PDF 位置感知版）

PDF 用 `page.get_text("dict")` 逐行提取（行 + bbox + 页码序号），每页按 Y 排序：

- **区域判定**：页眉区 = 页高前 8%，页脚区 = 后 8%（正文行落入该区域不必然删，需满足下述条件之一）；
- **页码模式**（命中即删，不论位置）：
  `^\d{1,4}$`（纯数字，含全角）｜`^第\s*\d+\s*页`｜`^-?\s*\d+\s*/\s*\d+\s*-?$`｜`^[—–-]\s*\d+\s*[—–-]$`｜罗马数字行；
  实测语料的 `— １ —` 被拆成三行，需**行级合并判定**：若页脚区连续三行分别是 `—`/`１`/`—`，整体删除（合并后匹配 `^—\s*\d+\s*—$`）；
- **跨页高频重复**（页眉典型：`四川省人民政府办公厅文件` 出现在 7/7 页页眉区）：规范化文本（去空白）相同、且都落在页眉区或页脚区、出现在 ≥50% 页 → 判为页眉/页脚行删除；
- **保护规则**：跨页重复但位置在正文区（如每页都出现的章节标题恰好在页中）不删；单页文档不做跨页判定（无统计意义），只删页码模式行。

### 3.3 阶段 4：段落重建（新模块 `services/paragraphing.py`）

输入物理行序列，输出自然段序列。规则按优先级：

1. **空行**（strip 后为空）→ 段落边界；
2. **标题行**（匹配条款/章节模式，如 `第三章`/`一、`/`（一）`/`1.`/`（1）`，且行长短）→ 强制开启新段；
3. **上一行以句末标点结尾**（`。！？；：`）**且当前行以标题模式或首行缩进（全角空格×2）开头** → 新段；
4. **括号跨行**（上行以 `（`/`《` 结尾，或本行以 `）`/`》` 开头）→ 合并；
5. 其余 → 软换行，与上行拼接：中文间直接拼；行尾/行首出现半角单词断裂（ASCII 字母数字相接）时补一个空格；
6. **收尾合并**：孤立的短行（< 8 字）若不匹配标题模式，向前合并（防落款/日期被切成独立碎块——但发文机关署名与日期保持独立，见例外）。

输出段落带原文偏移（与 chunker 的 `_Unit` 偏移机制衔接，供父子挂载）。

### 3.4 阶段 5：切分重写（`services/chunker.py`）

**核心变化：`paragraph` 策略的单元从"句子"改为"自然段"。**

| 策略 | 单元 | 适用 |
|---|---|---|
| `paragraph`（默认，重定义） | 自然段（阶段 4 产物） | 默认；段内不切，跨段合并至预算 |
| `sentence` | 句子 | 问答型检索（用户显式选择） |
| `section` | 标题+其下正文 | 条款级结构文档 |
| `fixed` | 无（定长窗口） | 结构稀疏场景 |

**段落优先切分算法**（`_merge_budgeted` 改造）：

```
units = 自然段序列（token 已批量计数）
buf = []
for u in units:
    if u.tokens + overhead <= budget:      # 整段放得下 → 整段入块（段内不切）
        buf.append(u); continue
    if u.tokens > budget:                  # 单段超预算 → 四级降级
        flush(buf)
        for piece in split_paragraph_graceful(u, budget):   # 见下
            emit(piece)
    else:                                  # 缓冲已满 → flush 后重新起 buf
        flush(buf); buf = [u]
flush(buf)
```

**`split_paragraph_graceful`（单段超预算的四级降级）**：

1. **句边界软切**：按 `。！？；` 切句，整句归整打包至预算（现有 `_soft_windows`，句号修复后锚点恢复）；
2. **单句仍超预算 → 子句边界**：按 `，、：` 切分句内子句，整子句归整打包；
3. 单子句仍超预算 → **词/字窗口硬切**（`_token_windows`，token 级，与 embedding 边界对齐）；
4. 硬切块间保留小重叠（≤ 预算 10%），缓解边界词腰斩。

每级都保证：不切断的不切，必须切时切在最接近的语义边界。**小块预算 300 token 下，200-500 字段落可整段成块，实测目标"段中切断 = 0"**（超长段除外，逐级降级）。

**双粒度不变**：small/large 复用同一单元序列与 token 计数，各自按预算合并；父子挂载 `mount_parents` 不变。large 预算 2500 下多数章节可整段落入，生成注入上下文完整。

### 3.5 OFD 独立库 `ofdkit`（用户要求"写成单独的完整库"）

```
backend/ofdkit/
├── pyproject.toml            # 独立可分发的包（stdlib 零三方依赖）
├── README.md                 # 库文档：用法/架构/扩展点
├── src/ofdkit/
│   ├── __init__.py           # 公开 API：extract_text / OFDDocument / TextRun ...
│   ├── model.py              # dataclass：TextRun(y,x,text,size) / OFDPage / ExtractResult
│   ├── reader.py             # ZIP 包导航：OFD.xml→DocRoot→Document.xml→Page→Content.xml
│   ├── textorder.py          # 坐标阅读顺序：Y 分行（容差 1.5mm）→ 行内 X 排序
│   ├── noise.py              # 页码/页眉页脚剔除（OFD 坐标版，同 3.2 算法）
│   ├── normalize.py          # 码点规范化映射表（与主服务同源，库保持独立自包含）
│   └── extract.py            # 主编排：extract_text(data) -> ExtractResult
├── ofdkit/__main__.py        # CLI：python -m ofdkit <file.ofd> 调试
└── tests/                    # 库自有 pytest（不依赖主服务）
```

设计原则：
- **零三方依赖**（纯 stdlib：zipfile/ElementTree/dataclasses），部署方可整体拷贝复用，不拖入主服务的 FastAPI/PG 依赖树；
- 公开 API 稳定：`extract_text(data: bytes, clean_noise: bool = True) -> ExtractResult`（`ExtractResult{text, pages, is_scanned, scanned_pages, noise_removed}`）；
- 坐标单位按 OFD 规范（mm，float），容差与算法同 PDF 版；
- 签章/无文字层页计入 `scanned_pages`（与 PDF 策略一致，OCR 二期兜底）；
- 主服务通过 **uv workspace** 接入（`[tool.uv.workspace] members=["ofdkit"]`），`parser.py` 改为 `from ofdkit import extract_text` 薄封装——主服务不再内嵌 OFD 实现，库可独立发版。

## 6. 风险与权衡

| 风险 | 缓解 |
|---|---|
| 跨页重复行误删正文（如每页都引用的同一法规名在页眉区） | 仅在页眉/脚区（8%）内判重；正文区不判；报告逐篇列出被删行供复核 |
