# 企业公文知识库 · 导出功能重新设计方案（V1.0）

> 适用范围：公文起草（draft）链路的一键导出 docx（二期扩展 pdf/ofd）。
> 关联需求：用户反馈「导出功能不可用 / 应导出已生成内容 / 导出按钮应在生成后出现 / 必须考虑多轮生成的版本管理」。
> 设计原则：**导出 = 导出已经落库的内容，绝不重新生成**；导出按钮**后置**到生成完成；多轮起草以「消息版本」天然实现版本管理。

---

## 1. 现状问题（为什么不能用）

当前 `POST /v1/export/docx` 接收完整的 `GenerateRequest`，内部调用 `generate_answer(db, req, caller)` **重新跑一遍检索 + 生成**，再把 `req.query` 当标题用 python-docx 渲染。由此产生四类问题：

| 问题 | 说明 | 后果 |
|------|------|------|
| 导出 ≠ 当前内容 | 重新生成，与页面已显示的正文**可能不一致**；无材料时会触发「通用能力起草 + 甄别声明」兜底 | 用户拿到的不是他看到的那一版 |
| 参数错误 | 前端 `exportDocx()` 只传 `{query, template_doc_type, caller_scope, max_clearance}`，**缺失 `conversation_id` / `message_id` / `template_code` / `space_ids`** | 模板语义、权限/密级语义丢失，版式与权限不可控 |
| 按钮常驻 | Draft.vue 中 `:disabled="!answer"` 但按钮始终渲染 | 无内容时按钮「灰着」也在，交互语义错误（应是生成后才出现） |
| 无版本管理 | 永远重新生成最新一版，无法选择历史某一轮 | 多轮修改后想导出前几稿做不到 |

---

## 2. 设计目标

1. **导出已生成内容**：按 `conversation_id` + `message_id` 精确定位会话内某一条 assistant 消息（即某一轮起草正文），直接渲染，**不再调用模型**。
2. **按钮后置**：只有「当前会话存在可导出内容（至少一条 assistant 消息且已 done 落库）」时，导出入口才出现。
3. **多轮版本管理**：一个会话内每轮起草 = `user(指令) + assistant(正文)` 两条消息；所有 `assistant` 消息按时间升序即 `V1、V2 … Vn`，用户可任选其一导出（默认最新版）。
4. **安全兜底不降级**：导出前对正文**再做一次敏感词脱敏 + 密级复核**（防御纵深），不因「内容已落库」而放松。

---

## 3. 核心概念：版本 = 会话内的 assistant 消息

数据模型已具备版本管理所需的全部字段（无需新增表）：

- `Conversation`（conv_type=draft，doc_type 文种，space_ids，title）
- `ConversationMessage`（conversation_id, role, content, citations, sensitive_hits, model, intent, reasoning, created_at）

**版本定义**：同一 draft 会话内，`role == 'assistant'` 的消息按 `created_at` 升序依次为 V1、V2 …；每条即一稿可导出公文。
**默认版本**：缺省取会话内**最新**一条 assistant 消息（V-latest）。
**历史还原**：前端「历史会话」点开某会话 → 加载其消息 → 可导出其中任意版本。

> 无需单独的版本表：会话消息本身就是版本日志，删除会话级联清理消息（含版本），无孤儿数据。

## 4. 后端接口设计

### 4.1 新增请求体 `ExportDocxRequest`（contracts.py）

```python
class ExportDocxRequest(BaseModel):
    """导出【已生成】内容：按会话 + 消息精确定位，不重新生成。"""
    conversation_id: str = Field(..., description="起草会话 ID（必填，定位会话）")
    message_id: str | None = Field(
        None, description="指定导出的 assistant 消息版本；缺省取会话内最新 assistant 消息"
    )
    template_code: str | None = Field(None, description="版式模板 code（可选，仅影响 docx 排版）")
```

> 废弃旧 `GenerateRequest` 入参：导出不再需要 query / rerank / space_ids 等生成参数。

### 4.2 改写 `POST /v1/export/docx`

流程（伪代码）：

```
1. 鉴权：caller.allows_scope("chat") 否则 403；req.max_clearance = caller.cap_clearance(req.max_clearance)
2. 取会话：SELECT Conversation WHERE id=conversation_id；不存在 → 404
3. 定位目标消息：
   - 若 message_id 给定：SELECT 该消息，校验其 conversation_id 匹配且 role=='assistant'，否则 400
   - 否则：取该会话内 created_at 最大的 assistant 消息
   - 仍无 → 400「该会话尚无可导出的起草内容」
4. 安全复核（防御纵深）：
   - 重新解析生效中的敏感词表（ConfigKV category=sensitive_word, is_active）
   - content, hits = redact_sensitive(target.content, words)   # 内容生成时已脱敏，这里再兜一层
   - 密级复核：target.citations 引用的文档密级若超出 caller.max_clearance → 拒绝导出并提示
5. 版式（可选）：若 template_code 给定且 assert_template_usable 通过，按模板渲染；否则默认公文版式
6. 渲染 docx：
   - 标题 = conversation.title（或该轮 user 指令前 20 字）
   - 正文按换行拆分为段落渲染；保留「参考资料」「敏感词命中」标注
7. 返回 FileResponse（filename = 标题前 20 字 + .docx）
```

要点：
- **不调用 `generate_answer`**，零模型算力、零检索、内容确定可复现。
- 敏感词二次脱敏 + 密级复核，与生成链路同等的出口安全。
- `template_code` 仅用于版式，仍走 `assert_template_usable`（他人模板不可用）校验。

## 5. 前端交互设计（Draft.vue）

### 5.1 导出按钮后置

删除常驻按钮，改为条件渲染：

```ts
const canExport = computed(
  () => !!activeId.value && !!lastAssistantMsgId.value && !loading.value,
)
// lastAssistantMsgId：本轮 done 后由 onDone 记录；或打开历史会话时由消息列表计算
```

仅当「存在 activeId 且该会话有 assistant 消息且不在生成中」时，才显示「导出 docx」入口。

### 5.2 版本选择弹窗

点击导出 → 拉取 `GET /v1/conversations/{activeId}`（已返回全部消息）→ 过滤 `role==='assistant'` → 渲染版本列表：

```
第 1 稿 · 2026-10-15 14:02 · 「关于…的请示」（前 24 字预览）
第 2 稿 · 2026-10-15 14:10 · 「关于…的请示（修改稿）」
…（默认高亮最新一稿）
```

用户点选某稿 → 关闭弹窗 → 调用导出。

### 5.3 client.ts 新增方法

```ts
export async function exportDocx(req: ExportDocxRequest): Promise<Blob> {
  return postBlob('/v1/export/docx', req)   // 接收二进制 docx
}
```

### 5.4 交互状态

- 导出过程单独提示「正在导出…」（**不**进 Agent 步骤面板，导出非生成过程）。
- 成功后浏览器触发下载；失败（如 400/403）弹错误提示。

## 6. 多轮版本管理细则

| 场景 | 行为 |
|------|------|
| 单轮起草后导出 | 仅 1 个版本（V1），直接导出 |
| 多轮「接着改」后导出 | 列出 V1…Vn，默认 Vn；可选历史稿 |
| 打开历史会话再导出 | 加载该会话消息，版本列表为该会话的全部 assistant 稿 |
| 删除会话 | 级联删除消息（含版本），无残留 |
| 删除单条消息 | 暂不支持（保持简单；会话级删除即可） |

版本标识建议：前端用「第 N 稿 · 时间 · 预览」展示；后端按 `created_at` 升序编号，保证跨端一致。

---

## 7. 安全兜底（不降级）

- 导出内容虽已落库脱敏，仍**二次 `redact_sensitive`**（敏感词表可能生成后更新）。
- **密级复核**：导出时校验所引文档密级 ≤ caller.max_clearance，超限**拒绝并提示**，杜绝「导出时泄露高密级片段」。
- 不重新检索/生成，从根上消除「导出又跑一遍模型」的算力浪费与结果不一致。

---

## 8. 验证方案

1. **基础导出**：起草一轮 → done → 导出按钮出现 → 选版本 → 下载 → 校验 docx 正文 == 该轮 assistant 消息 content。
2. **版本切换**：多轮起草 → 分别选 V1 / V2 导出 → 校验内容对应各自轮次。
3. **历史会话导出**：打开历史会话 → 导出 → 校验取的是该会话版本。
4. **空会话/无内容**：message_id 指向不存在消息 → 400；会话无 assistant 消息 → 400「尚无可导出内容」。
5. **安全**：构造含敏感词/高密级引用的消息 → 导出时二次脱敏生效 / 密级超限拒绝。
