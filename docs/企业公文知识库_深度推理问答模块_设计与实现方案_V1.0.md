## 0.1 V1.2 变更说明（2026-10-19）

| # | 用户要求 | 变更 |
|---|---|---|
| 1 | **取消轮数配置，默认无限轮步骤直到完成任务** | `deep_max_rounds` 默认 `0` = **不限轮数**；`deep_budget_ms` 默认 `0` = **不限时长**。引擎主循环由 `for round in range(1, max_rounds+1)` 改为 `while True`（`0` 不能退化成"零轮"）。**档位不再用轮数/时长区分**，改为检索广度：`fast` 4 召回/4 注入、`deep` 8 召回/8 注入 |
| 2 | **不限轮不能变成无限空转** | 新增 `deep_no_progress_limit`（默认 3）：连续 N 轮无**新增引用** → 第 N-1 轮注入"换角度或收尾"提示、第 N 轮强制收尾（`stop_reason=no_progress`），随后照常生成完整答案。其余护栏（决策失败/解析失败各 2 次）保留 |
| 3 | **支持提示词配置** | 三段提示词（理解 `deep_prompt_understand` / 决策 `deep_prompt_decision` / 最终生成 `deep_prompt_final`）支持配置中心整段覆盖，空=内置默认；新增 `GET/PUT /v1/chat/react/prompts`（PUT 限 admin），保存即生效；前端抽屉支持编辑/保存/恢复默认 |
| 4 | 提示词变量注入方式 | 由 `str.format` 改为 `str.replace` 显式 token 注入（`{tool_lines}`/`{max_rounds}`/`{round_rule}`/`{material_rule}`）——提示词正文含大量 JSON 花括号，`format` 会抛 `KeyError` |

实测（真实 Qwen3）：默认配置下模型连续 7 轮自主检索后 finish（旧实现 deep 档 5 轮即被截断）；`no_progress_limit=3` 时持续空转在第 3 轮被强制收尾；提示词保存后下一次问答立即生效。pytest 252 全绿。

## 0.2 V1.3 变更说明（2026-10-19）：智能起草 ReAct 化——由模型自主决策

需求原文（用户 2026-10-19）：**「智能起草公文也修改为按深度思考问答的方式来生成公文，由模型来自主决策」**。

即：`/v1/generate`（智能起草）从"意图识别 → 单趟检索 → 直接成稿"改造为与深度推理问答**同构的 ReAct TAO 循环**——是否检索、查什么关键词、要不要打开原文核对、何时收尾，全部由模型逐轮自主决策，材料够了再成稿；过程可见、不拒答、多轮上下文（上一稿）不丢。

### 0.2.1 变更清单

| # | 用户要求 | 变更 |
|---|---|---|
| 1 | 起草按深度思考方式生成、模型自主决策 | 起草链路复用 ReAct 引擎（`run_react(pack=DRAFT_PACK)`），编排层**零"要不要检索"前置判断**；模型 finish = 依据已足够，交由系统成稿 |
| 2 | 起草与问答提示词不同（模型须知道自己在"收集起草依据"而非"回答问题"） | 新增 `TaskPromptPack` 双通道：差异化部分（智能体身份/finish 语义/停止原因中文标签/工具播报用词/历史截断长度）全部收敛进 pack，**引擎与编排零分支** |
| 3 | 起草任务语义注入 | 新增 `_build_draft_task_context`：首条决策消息注入【任务类型】公文起草、【目标文种】、【采用模板】、任务说明、多轮修改注意事项 |
| 4 | 引用材料防膨胀 | 新增 `_cap_citations`（1500 字/条）：`read_document` 原文可达 4000 字，多条注入会挤爆成稿 prompt；只裁剪**注入模型的副本**，落库与前端展示保留完整 |
| 5 | 成稿提示词不搞两处可改 | 起草成稿提示词复用配置中心「提示词模板」的 `draft_system` / `no_materials_system`，ReAct 提示词面板内以 `source=external` **只读预览**，避免双入口互相覆盖 |
| 6 | 成稿不被截断 | 起草链路 `max_tokens=8192`——Qwen3 思考链与正文**共用 max_tokens**（深度问答实测 1500 时正文仅 157 字断尾，已踩过的坑） |
| 7 | 起草也要"AI 生成"声明 | 成稿末尾统一追加 `DRAFT_DISCLAIMER`（正文标注的引用内容请核对原文），落库 `disclaimer=True` |
| 8 | 起草推理过程用户可见 | SSE 全量透传 react_*/phase 事件（`react_start.channel="draft"`）；前端 Draft.vue 新增深度推理开关（localStorage 持久化、null=跟随后端 `deep_draft_enabled`）、档位单选、阶段播报条、`ReActTracePanel channel="draft"`、提示词抽屉 |
| 9 | 隐性回退防护 | `deep_reason` 缺省跟配置 `deep_draft_enabled`（默认开）；显式 `deep_reason=false` 完全回退单趟链路。同时修复 Chat.vue：deep 问答默认全开后问答页此前**未注册 react handler**（事件静默丢弃=思维链丢失的复发模式），已补齐全套 handler |

### 0.2.2 设计要点

**引擎复用而非复制**：起草与问答的 TAO 结构完全相同（自主决策调用工具收集依据 → 够了 finish → 最终生成），差异仅有"智能体身份 / 提示词 / 停止原因标签 / 播报用词 / 历史截断长度"，全部收敛到 `TaskPromptPack`（`react_prompt.py`），`run_react` 本体与 `stream_generate` 编排**不含任何通道分支**：

| pack 字段 | QA_PACK（问答） | DRAFT_PACK（起草） |
|---|---|---|
| understand_system | 提问理解器 | 起草需求理解器（识别文种/主题/材料诉求） |
| decision_template | 智能体身份="知识库问答助手" | 智能体身份="公文起草"，finish 语义="依据已足够，交由系统成稿"，**红线：不得编造文号/指标/人名** |
| stop_labels | 分享 STOP_REASON_LABELS | 起草版文案（"依据已足够（模型主动结束，开始起草）"等） |
| tool_phase_labels | 检索知识库 / 查找文件 / 打开原文 | 检索起草依据 / 查找候选文件 / 打开原文 |
| history_hint_chars | 500 | **1200**（多轮修改须让模型知道上一稿文种与篇幅） |

**起草专属处理**（`services/generation.py`）：
- `_stream_draft_react` 四步 plan：`understand → collect（react 循环）→ generate（成稿）→ redact（脱敏落库）`；
- 成稿 messages 注入 `【推理过程】`（`format_process_summary` 汇总每轮 Thought/Action/Observation），让成稿模型知道"依据是怎么收来的"；
- 零材料**不拒答**：切配置中心 `no_materials_system` 分支走通用公文规范成稿，并标注"知识库暂无对应规定"；
- `generate_answer`（非流式第三方接口）同样分流至 `_generate_answer_react`，行为对齐。

**测试**：`test_draft_multiturn_integration.py` 重写为双态测试——单趟链路 mock `load_react_config(draft_enabled=False)` 锁死"第二轮必须注入上一稿"；ReAct 链路 mock `run_react` 脚本化事件序列，验证 react_* 透传、`channel=="draft"`、成稿 prompt 含【推理过程】/引用/上一稿、免责声明落库。`test_react_engine.py` 追加起草包提示词生效、问答通道回归保护、draft 通道导出、默认值。**pytest 258 全绿**（252 → 258）。

## 0. V1.1 重构说明（用户评审反馈 → 逐条落实）

用户实际体验后指出 6 个问题，全部为**架构级**，已逐条重构并用真实模型验证：

| # | 用户反馈 | 根因 | V1.1 改法 |
|---|---|---|---|
| 1 | 页面完全没有思维链体现 | `ReActTracePanel` 渲染在**消息列表之外**（列表与输入框之间），且 Thought 用 `white-space: nowrap` 单行省略——长思维链视觉上等于不存在 | 面板**内联到消息流**答案上方；TAO 段落全部改完整多行、零截断；命中明细展开显示标题+摘要全文 |
| 2 | 问题分析/推理循环/工具调用过程没体现 | 旧版只在 `single_hop=false` 时才渲染"查询分析"块，单跳问题整块隐藏 | 理解阶段**始终展示**：诉求复述、模型自述是否查库、候选方向、待澄清点 |
| 3 | 还是一上来就开始检索，和之前一条链路没区别 | ① `ANALYZE_SYSTEM` 有 `single_hop`（"单跳直接检索"降级短路）；② `_run_react` 零引用时**无条件兜底再检索一次**；③ 工具只有 2 个且不能看原文 | **删除 single_hop 与全部降级分支**；删除强制兜底检索；新增 `read_document`（模型自主打开原文核对条款）；是否检索/用哪个工具/何时收尾**全部由模型逐轮自主决定** |
| 4 | 提示词管理不可见 | 无暴露接口 | 新增 `GET /v1/chat/react/prompts` + 前端「提示词」抽屉：四阶段提示词全文 + 工具契约，所见即所跑 |
| 5 | 不支持多轮上下文 | ReAct 决策历史只有 `req.query`，**完全不含会话历史** | `run_react` 新增 `history` 参数，会话历史注入决策上下文（指代消解前提） |
| 6 | 无材料就拒答，但用户要的是完成任务 | `_run_react` 零引用 → 固定话术拒答 | **删除拒答路径**：零材料也进最终生成（切"通用知识兜底"分支并标注依据不足），末尾统一附「AI 生成，请人工鉴别」 |

实测对照（真实 Qwen3，非 mock）：

| 场景 | 结果 |
|---|---|
| 通用常识（"公文标题怎么拟"） | 模型自述 `needs_knowledge=false` → **第 1 轮直接 finish，零工具调用**，5.4s / 1123 字完整答案（自动标注"知识库暂无对应规定"） |
| 查库问题 | 5 轮自主决策：`knowledge_search` → `read_document`（打开原文）→ `knowledge_search` → `doc_lookup`，13 条引用，26s |
| 多轮追问（"它的适用范围是什么"） | 模型思考中明确引用上一轮结论完成指代消解 → 正常作答 1013 字 |

## 1. 需求理解与目标

### 1.1 需求拆解（必须逐项落地的能力）

| # | 需求点 | 本方案落点 |
|---|---|---|
| 1 | 查询分析：判断是否需要拆解为多个子问题 | §5.3 提问理解阶段（**V1.1 重构**：只让模型复述诉求并自述是否查库，不做任何路由，见 §0） |
| 2 | ReAct 推理循环：Thought → Action → Observation 动态迭代 | §5.4 ReAct 引擎主循环 |
| 3 | 工具调用：核心为知识库检索工具（`rag_retrieve_tool`），预留数据库/网络扩展 | §5.5 工具协议与注册表 |
| 4 | 迭代决策与停止：信息充足退出 / 不足继续 / 换关键词重试 | §5.4 停止条件与护栏 |
| 5 | 最终生成：综合多轮信息、交叉验证、按来源权威性排序 | §5.7 汇总生成 |
| 6 | 完整推理思维链，SSE 友好展示 | §5.8 SSE 事件协议 + §6 前端 TAO 时间线 |

### 1.2 设计目标（验收口径）

1. **多跳问题**（对比、多条件、排查根因、跨文档综合）回答质量显著优于单轮检索——以评测台指标验收（§7），不以感觉验收；
2. 思维链**完整可见、可回看、可审计**（每轮思考/行动/观察结构化展示并落库）；
3. **安全红线不破**：检索工具内部复用现有密级/权限 WHERE 下推，不新增任何数据通路；
4. **可用性红线不破**：理解/工具/决策任一环节失败都**不阻断任务**（不降级为"单跳直接检索"，也不拒答）；材料不足时基于通用知识完成作答并标注依据（§5.7）；
5. 延迟与成本**显式可控**：默认不限轮（由无进展护栏收敛），运维可设轮数/时长硬闸，全过程实时可见。

## 2. 与现有智能问答的区别

| 维度 | 现有 direct_qa（单轮检索直答） | 现有 complex_task（分步执行） | **本模块 deep_reason（ReAct）** |
|---|---|---|---|
| 检索次数与时机 | 1 次，query 原样 | 1 次拆步后**按计划**每步 1 次，计划一次定死 | **动态 N 轮**，每轮检索什么由"上一轮观察 + 当前思考"决定 |
| 思考链 | 模型隐式 `reasoning_content`，不可控、不作为决策依据、不展示流程 | 无独立思考链；步骤是规则模板/LLM 一次性拆出的 | **显式结构化 Thought**（模型每轮自主输出），前端逐轮展示，落库可回看 |
| 工具 | 无工具概念，代码直接调 `retrieve_enhanced` | 代码内置 retrieve/generate 两动作 | **工具注册表**：`knowledge_search` / `doc_lookup`，模型自选 |
| 停止条件 | 无（一次到底） | 计划步骤执行完 | 模型自评充足主动 `finish`（默认唯一正常出口）/ 连续无进展 / 解析失败 / 决策失败（轮数、预算为可选硬闸） |
| 多跳/对比问题能力 | 弱（单查询召回受 query 稀释） | 中（固定三模板：对比/汇总/排查） | **强**：可逐步收窄、换角度重检、分别检索对比双方 |
| 引用 | 单轮 top-N | 按步骤合并去重（≤8） | 逐轮聚合并重排序（≤N，按相关度+来源权威） |
| 延迟 / token 成本 | 低 | 中 | **高**（多轮 LLM 决策 + 多轮检索，数秒~数十秒；prompt 逐轮累积） |
| 失败模式 | 无材料拒答 | 步骤失败仍汇总 | 需护栏防"死循环/重复检索"（§5.4），且整体可降级 |

一句话：**现有问答是"单次管道 + 固定剧本"，本模块是"模型自主决策的多轮搜索循环 + 透明思维链"**。

## 3. 优点与缺点

### 3.1 优点

1. **多跳问题覆盖率与正确率提升**："A 和 B 的差异"可分别检索 A、B 再比对；"排查类"可先查现象、再查处置规范，逐步逼近答案，不受单次 query 语义稀释影响；
2. **过程透明、可信、可审计**：思维链逐轮可见，用户能回答"这个结论是怎么来的"，配合引用编号可核对，是**显式抑制幻觉的机制**（而非事后声明）；
3. **按需检索**：信息够了立即停，避免"一次塞 8 条"的上下文稀释；信息不足才追加检索，检索质量由模型反馈闭环驱动；
4. **工具可扩展**：新增工具（如文档元数据查询）只需注册，主循环零改动；
5. **复用存量资产**：检索（RRF+rerank+改写+父块注入+权限下推）、生成、脱敏、审计、会话落库全部复用，不造新引擎；
6. **体验差异化**：SSE 逐轮推送让长推理"有来有回"，用户感知从"卡住等答案"变为"看 Agent 工作"。

### 3.2 缺点与缓解措施

| 缺点 | 影响 | 缓解措施 |
|---|---|---|
| **延迟高**：每轮 1 次 LLM 决策调用 + 1 次检索（含 rerank ~6.5s），3 轮即数十秒 | 体验风险 | 实时阶段播报 SSE（`phase`）+ 推理链逐轮可见；提供"停止"随时中断；简单问题模型第 1 轮即可 finish；运维可设 `deep_budget_ms` 硬预算 |
| **token 成本高**：observations 逐轮累积注入 prompt | 32B-INT4 上下文压力 | 观测截断（snippet ≤160 字、命中按档位 4/8 条、历史轮摘要化）；`no_progress_limit` 收敛；累计引用上限 |
| **模型决策可能退化**（重复检索同一 query、格式不合法、过早 finish） | 质量问题 | JSON 宽容解析 + 连续 2 次解析失败退出；query 去重跳过；连续 2 轮无新命中强制收敛；few-shot 约束 |
| **实现复杂度高**：状态机、护栏、SSE 事件面扩大 | 维护成本 | 引擎纯函数化（输入状态→输出事件），可单测；失败路径全部预案化 |
| **模型规模依赖**：32B-INT4 决策质量优于小模型但仍需 prompt 工程 | 效果风险 | 决策调用低温度（0.1~0.2）+ few-shot；评测台按问题集回归（§7） |
| **会话与历史的语义边界**（历史轮 vs 本轮循环） | 复杂度 | 循环 only 针对本轮 query；会话历史仍按现有机制注入最终生成阶段 |


### 5.3 提问理解（Understand，**仅作参考，不做路由**）

一次轻量 LLM 调用（temperature=0，max_tokens=400，超时 10s），输出 JSON：

```json
{"restate": "用你自己的话复述用户诉求",
 "needs_knowledge": true,
 "needs_knowledge_reason": "为什么需要/不需要查库",
 "candidates": ["可选检索方向，最多4个"],
 "ambiguities": ["需要澄清的点，没有则空数组"]}
```

**红线（V1.1 起）**：结果只作为"上下文提示"注入决策历史，**引擎不据此分支**——`AnalysisResult` 已无 `single_hop` 等可驱动路由的字段（结构上保证无法自动降级）。理解阶段失败/超时/不可解析**不阻断循环**，只是少一段参考，`analysis` 事件注明"理解阶段跳过"。


### 5.4 ReAct 引擎主循环

#### 5.4.1 循环体（单轮）

```
每轮 round (1..∞；仅当 deep_max_rounds>0 时才是 1..max_rounds):
  1. 预算检查: 仅当 budget_ms>0 且已耗时 > budget_ms → stop_reason="budget"，跳出
     （注意 0 = 不限，不能用 falsy 判断成"立刻超预算"）
  2. 决策调用: messages=[system, ...history, observations] → gen.generate(JSON, max_tokens=512, extra_body=enable_thinking=False)
     - 超时/异常: decision_fail +=1
        decision_fail >= 2 → stop_reason="decision_fail"，跳出（进入 final，用已收集材料）
        decision_fail < 2  → 注入"上次决策失败，请重试"观察，继续
  3. 解析 JSON（宽容）:
     失败: parse_fail +=1；连续 2 次 → stop_reason="parse_fail"，跳出
  4. 产出 thought 事件；if action.tool == "finish" → stop_reason="final"，跳出
  5. 产出 action 事件；查工具注册表:
     未注册工具 → 观察"无此工具"，continue
  6. 执行工具(knowledge_search/doc_lookup/read_document) → 产出 observation 事件
     - 与历史 query 去重（归一化后完全相同）→ 观察标注"重复检索已跳过"，不调工具
     - 连续 N-1 轮无新引用 → 注入"换角度或收尾"提示（给模型纠偏机会）
     - 连续 N 轮无新引用 → stop_reason="no_progress"，跳出（强制收尾后仍生成答案）
  7. 新引用并入 ctx.citations（按 chunk_id 去重）
循环结束 → finalize(stop_reason)
```

#### 5.4.2 护栏总表（防退化）

| 护栏 | 触发 | 行为 |
|---|---|---|
| 轮数上限（**可选**） | `max_rounds>0` 且 `round > max_rounds` | 退出循环，finalize("max_rounds")。默认 `0`=不限，不触发 |
| 全局预算（**可选**） | `budget_ms>0` 且累计耗时 > 预算 | 退出，finalize("budget")。默认 `0`=不限，不触发 |
| **无进展强制收尾** | 连续 `no_progress_limit` 轮无**新增**引用 | 第 N-1 轮注入"换角度或收尾"提示；第 N 轮 finalize("no_progress") |
| 决策失败容忍 | 决策调用异常/超时 | 首次注入重试提示；连续 2 次退出 finalize("decision_fail") |
| 解析失败容忍 | JSON 不可解析 | 首次回灌纠错；连续 2 次退出 finalize("parse_fail") |
| query 去重 | 与历史检索 query 归一化相同 | 跳过真实工具调用，观察标注跳过（计入无进展） |
| 工具白名单 | action.tool 不在注册表 | 观察"无此工具"，不执行 |

#### 5.4.3 停止原因语义（透出前端 + 落库）

`final`（模型主动）/ `max_rounds`（仅设了硬闸时）/ `budget`（仅设了预算时）/ `no_progress`（无进展强制收尾）/ `parse_fail` / `decision_fail`。

> **产品语义（V1.2）**：轮数上限与预算默认都关闭，"不限轮"由**无进展护栏**兜底——不限轮 ≠ 无限空转。

### 5.5 工具协议

#### 5.5.1 工具注册表

| 工具 | 入参 | 实现 | 说明 |
|---|---|---|---|
| `knowledge_search` | `{"query": "..."}` | `retrieve_enhanced`（top_n 按档位：fast=4 / deep=8） | 核心。**内部已完成密级/权限/空间下推** |
| `doc_lookup` | `{"query": "标题/文号/关键词"}` | 复用文档可见性过滤链路 | 元数据级查询（"有没有关于 X 的文件"），仅返文档摘要，不返正文 |
| `read_document` | `{"query": "32位 chunk_id 或 标题/文号"}` | 切片层查询（含相邻片）或按文档取原文 | **V1.1 新增**：读原文核对条款。按 4000 字符预算渐进返回，`note` 说明剩余量与下步建议（防模型反复试读空转） |

> **网络搜索工具：本版本不提供**——私有化内网部署禁出网（涉密红线）。工具协议抽象已预留，未来如有合规的"内部站点检索"可注册即用。
> **任意数据库查询工具：不提供**——直连 SQL 有越权风险；结构化查询需求由 `doc_lookup` 覆盖。

#### 5.5.2 决策输出协议（模型每轮唯一输出）

```json
{"thought": "已知…，尚缺…，因为…所以下一步…",
 "action": {"tool": "knowledge_search", "query": "具体的子问题"}}
{"thought": "材料已覆盖问题，可交叉验证作答",
 "action": {"tool": "finish", "query": ""}}
```

- 宽容解析：截取第一个 `{...}`；`action`/`thought` 字段缺失/类型不符 → parse_fail；
- `query` 归一化用于去重（去空白、统一标点、小写）。

#### 5.5.3 Observation 结构（注入 prompt + SSE 推送同源）

```json
{"type": "observation", "round": 2, "tool": "knowledge_search",
 "query": "A产品华东区销售额",
 "hits": [{"n": 1, "title": "…", "doc_no": "…", "snippet": "…≤160字", "score": 0.62}],
 "quality": {"top_vector_distance": 0.31, "keyword_hits": 3, "rerank_top1": 0.72},
 "note": ""}
```

- `note` 承载：空结果 / 重复跳过 / 无新信息 / 工具异常 / 连续无进展提示；
- 质量信号帮助模型（与人）判断"这轮检得行不行"。

### 5.6 Prompt 设计（决策调用）

**system prompt（草稿，随评测迭代）**：

```
你是企业公文知识库的「深度推理问答」智能体，通过多轮调用工具收集证据，最后给出有依据的回答。
每一轮你只能输出一个 JSON 对象，不得输出任何其他文字，三种形态：
1) 调用工具：{"thought": "…", "action": {"tool": "knowledge_search", "query": "具体子问题"}}
2) 打开原文：{"thought": "为什么需要看原文", "action": {"tool": "read_document", "query": "<chunk_id 或标题>"}}
3) 直接作答：{"thought": "…", "action": {"tool": "finish", "query": ""}}
可用工具：
{tool_lines}
规则：
1. **是否需要检索、是否需要看文档，由你根据问题自行判断**（通用常识可直接 finish）；
2. query 要具体、可检索，一次只查一个点；对比/多实体问题分别检索；
3. 观察为空或不相关时，换关键词或换角度重试，禁止原样重复；
4. **任何情况下都不要放弃任务**：查不到也要基于通用知识完成作答并说明依据不足；
5. 信息足够就 finish，不要为问而问。
{round_rule}
```

- `{round_rule}` 在 `max_rounds=0` 时注入"**不设轮数上限**——需要几轮就做几轮，但禁止机械重复"；设了硬闸时注入"本轮上限 N 轮"。
- 提示词可被配置中心 `deep_prompt_decision` 整段覆盖（覆盖文本仍可引用上述占位符）。

**messages 组装**（每轮）：

```
system: 如上
assistant: 第 k 轮决策 JSON
user: "[观察 k] tool=… query=… 命中 n 条：…"（结构化文本块）
```

**预算控制**：历史轮观察摘要化（保留 thought + 命中标题列表 + note，snippet 仅保留最近 1 轮完整版），观测注入上限按 §5.2 配置执行。

### 5.7 最终生成（Finalize）

1. 引用聚合：`ctx.citations` 按 chunk_id 去重，按**相关度降序**（无 rerank 分则 RRF 分）；`deep_source_priority` 非空时同分按文种优先级排序；截断至 `deep_max_citations` 并**全局重编号 [1..N]**；
2. 构造最终 messages（复用 `build_final_messages` 的同类结构，增加"多轮检索综合/交叉验证"指令）：
   - "以下材料来自多轮检索，可能存在过时或相互矛盾的表述；**相互矛盾的条款须并列指出并说明以哪份为准（通常新规定/上级规定优先）**"；
   - "结论标注引用 [n]"；
   - 注入会话 history（多轮追问语境）；
3. 无材料分支（**V1.1 红线：不拒答**）：`ctx.citations` 为空 → 仍进入最终生成，prompt 切到"通用知识兜底"分支——要求**完成**回答、不得拒答、标注「知识库暂无对应规定，请以实际收到的正式文件为准」，末尾统一附「AI 生成，请人工鉴别」；
4. 流式产出（`generate_stream`）+ meta（含最终引用）/ token / done；模型思考链走 `reasoning` 事件（前端需注册 handler，否则丢失）；
5. 最终生成 system prompt 可被 `deep_prompt_final` 整段覆盖（支持 `{material_rule}` / `{has_material}` 占位符）。

### 5.8 SSE 事件协议（新增 9 类事件，向后兼容）

| 事件 | 载荷 | 前端行为 |
|---|---|---|
| `phase` | `{phase, label, round?, tool?}`；`phase ∈ start/classify/understand/decide/tool/answer` | **阶段播报**：显示"正在做什么 + 已等待 Ns"，消除 2–15s 静默期（2026-10-16 新增，修"页面像卡死"） |
| `react_start` | `{mode:"react", max_rounds, unlimited_rounds, total_budget_ms, tools[]}` | 初始化 TAO 面板；**`max_rounds=0` + `unlimited_rounds=true` → 显示"不限轮数"** |
| `analysis` | `{restate, needs_knowledge, needs_knowledge_reason, candidates[], ambiguities[]}` | 提问理解卡（诉求复述/是否查库/候选方向/待澄清） |
| `react_round` | `{round, max_rounds, unlimited_rounds}` | 时间线新增"第 N 轮"容器（运行中呼吸点） |
| `thought` | `{round, text}` | 轮内 Thought 渲染（**完整多行，禁止单行截断**） |
| `action` | `{round, tool, query, skipped?}` | 轮内 Action 徽标 + query |
| `observation` | `{round, tool, query, hits[], quality{}, note, elapsed_ms, hits_total}` | 轮内命中文档 + 质量信号；`full_snippet` 展示全文 |
| `react_end` | `{rounds, stop_reason, stop_label, citations_total, total_ms}` | 时间线收尾条（停止原因中文映射，含 `no_progress`） |
| `reasoning` | `{text}` | 模型隐式思考链增量（量大，需节流渲染；**DeepQa 曾漏注册导致"没有思考过程"**） |

> 老客户端忽略未知 type，完全兼容；最终答案仍走既有 `meta/token/done`。

### 5.9 权限与密级（红线，逐条对应）

1. 工具 `knowledge_search` = `retrieve_enhanced` → `build_visibility_filter` 下推 + `space_ids` + `max_clearance`（调用方额度已在入口 `cap_clearance`）；
2. `doc_lookup` 复用 `visible_space_ids` + 空间可写校验；
3. **观察内容即检索结果，天然不含越权数据**（查不到 = 观察为空）；
4. 最终落库/脱敏/审计完全复用 `chat.py` 收尾，零新增数据出口；
5. 审计 `record_audit`：意图识别行追加 `mode=react rounds=N stop_reason=… tools=[…]`。

### 5.10 降级与红线（任何一步失败，"用户的问题不失败"）

| 失败点 | 降级行为 |
|---|---|
| 查询分析失败 | 降级 single_hop，循环照常 |
| 决策调用连续 2 次失败/超时 | 用已收集材料（如有）直接 finalize；无材料 → 单轮检索兜底 |
| 决策 JSON 连续 2 次不可解析 | 同上 |
| 检索工具异常 | observation 记 error，模型可换角度；若一直异常 → 有旧材料则 finalize，无则兜底直答 |
| 全局预算耗尽 | finalize with 现有材料 |
| 策略整体异常 | `chat.py` 既有 except → error 事件 + 已生成部分保留 |
| 深度开关异常/配置缺失 | 回落现有策略矩阵 |

### 5.11 落库与会话

- assistant 消息 `reasoning` = **格式化 TAO 全链文本**：
  ```
  【查询分析】单跳=否；子问题：A/B…
  【第1轮】思考：… → 行动：knowledge_search("…") → 观察：命中3条（《…》…）
  【第2轮】… → finish（停止原因：信息充分）
  ```
- `citations` = 最终全局引用；`intent = "deep_reason"`；`sensitive_hits/model` 同现有；
- **不改消息表结构**（无迁移），历史消息打开即回看完整思维链（折叠面板）。

### 已实现并实测的关键结论
- **决策调用必须拿到原始问题**（真实端到端踩坑：决策历史仅含system prompt 时，模型回「用户尚未提出具体问题」→ 0 引用直接 finish）。现首条 user 消息注入原始问题 + 分析出的子问题清单，并有单测锁死（`test_react_first_decision_sees_user_query`）。
- **兜底链有效**：循环零引用（决策连续失败 / 过早 finish）→ 自动单轮检索复检 → 仍无 → 委婉拒答，**问题永不失败**。
