# 智能体（Agent）意图路由与分步执行方案

> 版本：V1.0（待确认） · 2026-10-13
> 适用范围：智能问答（/v1/chat）、公文起草（/v1/generate）及后续所有涉及生成的链路
> 状态：**方案待用户确认后开发**（本文档只做设计，不改代码）

---

## 一、需求理解

用户原话："智能问答，公文起草这类所有涉及生成的功能，都应有 agent 概念，即我们应该首先判断用户意图（希望确切回答，还是完成复杂任务等），然后基于意图来分步骤来完成任务。"

拆解为四个设计目标：

| # | 目标 | 含义 |
|---|------|------|
| G1 | **意图先行** | 每次生成请求先判断用户想干什么，再决定执行策略，杜绝"一把梭"式检索+生成 |
| G2 | **分步执行** | 复杂任务拆解为有序步骤，逐步推进、逐步可见，而非一次黑盒输出 |
| G3 | **全链路覆盖** | 问答、起草及未来所有生成功能共用同一套 Agent 内核，不各写一套 |
| G4 | **不破底线** | 意图判断失败/超时/模型抖动时，必须降级为现有直答链路，绝不允许" agent 坏了就连问答都用不了" |

## 二、总体架构

```
                 ┌────────────────────────────────────────────┐
                 │               Agent 内核（新增）            │
                 │                                            │
  用户请求 ─────▶│  ① 意图路由器 IntentRouter                  │
                 │      ├─ 规则通道（关键词/正则/长度/标点）    │
                 │      └─ LLM 通道（小模型分类，3s 超时）      │
                 │                    │                       │
                 │                    ▼                       │
                 │  ② 计划器 Planner（仅复杂任务）             │
                 │      任务 → 步骤列表（子问题/章节/校验）     │
                 │                    │                       │
                 │                    ▼                       │
                 │  ③ 执行器 Executor                         │
                 │      每步复用现有 检索/生成/模板 能力        │
                 │                    │                       │
                 │                    ▼                       │
                 │  ④ 汇总器 Aggregator → 脱敏 → 落库          │
                 └────────────────────────────────────────────┘
                                      │
                    SSE 事件流扩展：meta(意图) → plan → step_* → token → done
```

**核心原则：Agent 是"编排层"，不是"新引擎"。** 检索（hybrid_retrieve）、生成（ModelProvider）、脱敏（redact_sensitive）、权限下推（build_visibility_filter）全部复用现有能力，Agent 只负责"何时调谁、按什么顺序调、失败怎么办"。

## 三、意图分类体系（Intent Taxonomy）

### 3.1 意图枚举

| intent | 说明 | 典型用户输入 | 执行策略 |
|--------|------|--------------|----------|
| `direct_qa` | 确切回答：单一事实/定义/流程查询 | "跨网传输系统覆盖哪些网域" | 单轮检索 + 直答（现有链路，零额外开销） |
| `complex_task` | 复杂任务：多实体、多条件、比较、汇总、排查 | "对比 A 空间和 B 空间的安全制度差异" | Planner 拆解 → 多步检索 → 分步综合 |
| `draft` | 公文起草：按文种生成文稿 | "起草一份三季度安全大检查通知" | 模板匹配 + 检索素材 + 按章节起草 |
| `chitchat` | 闲聊/与知识库无关 | "你好" "你是谁" | 不走检索，直接礼貌回应（省 token） |
| `out_of_scope` | 超出知识范围且无法回答 | "今天天气怎么样" | 明确拒答 + 说明能力边界，**不编造** |

> `draft` 与现有 `/v1/generate` 的 template_doc_type 关系：template_doc_type 显式指定时视为强意图信号，直接进入 draft 策略，跳过分类（用户显式选择优先于推断）。

### 3.2 意图路由：规则通道 + LLM 通道（双通道，规则优先）

**规则通道（零成本、零延迟、确定性高）**——按优先级匹配：

1. 显式信号：请求带 `template_doc_type` → `draft`
2. 起草动词：包含「起草/拟/写一份/撰写/生成一份…通知/报告/请示/函」→ `draft`
3. 复杂任务信号：
   - 多问句（≥2 个问号或"并且/以及/同时/分别"连接多个分句）
   - 比较词（对比/差异/区别/哪个更/优劣）
   - 汇总词（汇总/统计/清单/一览/全部列出）
   - 排查词（为什么失败/如何排查/原因/定位）
4. 简单问句（单一问句、无上述信号）→ `direct_qa`
5. 命中闲聊模式（问候/自我介绍/感谢）→ `chitchat`

**LLM 通道（规则不自信时兜底）**：

- 触发条件：规则通道未命中任何信号（如陈述句、无标点的短输入）
- 实现：一次轻量分类调用（`ModelProvider(role="gen")`，`max_tokens=64`，temperature=0，prompt 要求输出 JSON `{"intent": "...", "confidence": 0.xx}`）
- 超时 3s；失败/超时/输出不可解析 → **默认 `direct_qa`**（保可用，G4）
- 分类结果写入审计日志（action=意图识别），可按意图统计用量

### 3.3 为什么不"纯 LLM 分类"

- 延迟：每次问答多一次完整 LLM 往返（本地 32B 模型 1-3s），直答场景不可接受
- 确定性：规则可预测、可测试、可解释；LLM 分类存在抖动（同一句话两次不同结果）
- 成本：内网算力有限，80% 以上的常见问答用规则即可覆盖

## 四、复杂任务的分步执行（Planner / Executor / Aggregator）

### 4.1 Planner：任务拆解

输入：用户 query + intent=complex_task
输出：有序步骤列表 `steps: list[Step]`

```python
Step = {
    "id": "s1",
    "action": "retrieve" | "generate" | "verify",   # 步骤类型
    "query": "子问题（检索步）或章节主题（生成步）",
    "depends_on": ["s0"],                            # 依赖（支持 DAG，本期先做线性）
    "status": "pending" | "running" | "done" | "failed",
}
```

拆解方式（与意图路由同构：规则优先 + LLM 兜底）：
- 规则模板：比较类 → ["分别检索 A", "分别检索 B", "生成对比表"]；排查类 → ["检索现象相关文档", "检索处置流程", "汇总排查路径"]
- LLM 兜底：输出 JSON 步骤列表（max_tokens=512，3s 超时，失败则退化为单步直答）
- **步骤数硬上限 6 步**（防失控；超过则该任务不适合分步，直接综合直答）

### 4.2 Executor：逐步执行

- 每步独立复用现有能力：`hybrid_retrieve`（带同一套权限/密级/空间下推）/ `ModelProvider.generate`
- 步骤间数据传递：后几步的 prompt 中注入前几步的产物摘要（截断至 500 字/步，防上下文膨胀）
- **每步开始/结束都推 SSE 事件**，前端实时渲染"步骤进度条"（用户看得见 agent 在干活，这是"分步"的体验核心）
- 单步失败：重试 1 次 → 仍失败则标记该步 failed 并**继续后续不依赖它的步骤**（部分失败好于全盘失败）；最终汇总时说明"第 N 步依据不足"

### 4.3 Aggregator：汇总

- 将各步产物 + 引用合并为最终答案，引用角标规则与现有链路一致（[n] 对应材料序号）
- 汇总后统一走 `redact_sensitive` 脱敏 + `sensitive_hits` 回报
- 汇总答案同样落库到会话（conv_type=chat，role=assistant，steps 概要存入 citations 之外的扩展字段或 detail）

### 4.4 SSE 事件序列扩展（向后兼容）

现有：`meta → token/reasoning → done → error`
扩展后：

```
meta（+ intent, plan 概要）
  plan（steps 列表，仅 complex_task）
  step_start（{id, query}）
  step_end（{id, ok, summary}）
  token / reasoning（汇总阶段的流式输出）
  done（answer + citations + sensitive_hits）
  error
```

前端兼容策略：老版本忽略不认识的 event.type 即可（switch default 分支），**接口不破坏**。

## 五、与现有链路的融合点（改动清单）

| 现有模块 | 改动 | 风险 |
|----------|------|------|
| `services/chat.py` | 入口增加 agent 编排：intent → 分支执行 → SSE 事件扩展 | 中（核心文件，需回归直答用例） |
| `services/generation.py` | 起草链路 intent=draft 时复用 Agent 的模板匹配与步骤化（多章节起草天然是 complex_task 的特例） | 中 |
| `schemas/contracts.py` | `ChatRequest`/`GenerateRequest` 增加 `agent_mode: bool = True`（可关闭，回退纯直答） | 低 |
| `api/routes/chat.py`、`generate.py` | 透传 agent_mode，无逻辑改动 | 低 |
| 审计 `_PATH_RULES` | 新增「意图识别」「任务计划」动作分类 | 低 |
| 配置中心 | 新增 `agent` 分类：开关、默认意图、步骤上限、LLM 分类超时（运维可调，无需发版） | 低 |
| 前端 Chat.vue / Draft.vue | 渲染意图标签与步骤进度（plan/step_start/step_end 事件）；老事件不变 | 低 |

**权限与安全的铁律不变**：每一步检索都走 `build_visibility_filter` + 空间过滤下推；敏感词脱敏只在最终输出执行；审计记录 intent/plan/steps。

## 六、降级与容错矩阵

| 故障点 | 现象 | 降级策略 |
|--------|------|----------|
| 规则+LLM 分类都失败 | intent 无法确定 | 默认 `direct_qa`，用户体验与今天一致 |
| LLM 分类超时（>3s） | 分类慢 | 放弃分类，走 `direct_qa`（不等） |
| Planner 输出不可解析 | 步骤列表坏 | 退化为单步直答（相当于 complex_task → direct_qa） |
| 某一步执行失败 | 步骤 failed | 重试 1 次 → 跳过该步继续，汇总时声明依据不足 |
| 汇总生成失败 | 最终无答案 | 推送 error 事件；已落库的部分步骤产物仍在会话中可查 |
| agent_mode=false | 运维关闭 Agent | 完全走现有直答链路（一行 if，零行为变化） |

## 七、分期实施计划

| 阶段 | 内容 | 验收标准 | 预估 |
|------|------|----------|------|
| **P1 意图路由** | 规则通道 + LLM 兜底 + intent 进入 SSE meta 事件 + 审计 | 5 类意图测试集准确率 ≥90%；分类失败时直答可用；延迟增加 ≤50ms（规则命中时 0） | 2-3 天 |
| **P2 分步执行** | Planner/Executor/Aggregator + plan/step_* 事件 + 前端步骤进度条 | 对比/汇总类任务分步可见；单步失败不影响总结；步骤上限生效 | 3-4 天 |
| **P3 体验打磨** | chitchat/out_of_scope 话术、意图标签展示、配置中心 agent 参数、按意图的用量统计 | 运维台可按意图看调用分布；可一键回退直答模式 | 1-2 天 |

每阶段独立可发布（P1 上线后 Agent 已"看得见意图"，P2 才"看得见步骤"），风险平滑。
