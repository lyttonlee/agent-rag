## 1. 文档接入与解析

### 1.1 接入方式
- 推送 API `POST /v1/documents`（单/批），请求体带原文引用或内联 + 元数据（按我方字段标准）。
- 文件投放：目录/SFTP 轮询 + CSV 元数据映射（离线批量）。
- 格式适配：不同公文系统导出布局经"格式适配器配置"适配，免改代码。

### 1.2 解析与结构化
- PDF：有文字层用 pdfplumber/PyMuPDF 提文本；无文字层/扫描件走 OCR 后路（PaddleOCR，预留）。
- docx：python-docx；wps：转 docx 后同上。
- 结构化抽取：标题、发文机关、文号、日期、文种、主送、正文分段。
- 元数据来自请求（external_id/security_level/permission_tags 等），原样存储。

### 1.3 清洗与切片
- 清洗：去页眉页脚/水印噪声、全半角归一、冗余空白。
- 切片：语义分块 ≈500 字，重叠 50 字。
- **上下文前缀**（提升召回）：`[标题｜机关｜文号｜日期｜路径]<正文切片>`。

## 2. Embedding 与入库

- 向量化：Qwen3-Embedding-4B → 1024 维；**定后不换**（换则全量重建）。
- 落库：`document` + `chunk`（含 `content_vec` vector(1024)、`tsvector_col`、`security_level`、`permission_tags`）。
- 索引：pgvector HNSW + tsvector(zhparser)；自定义词典注入 zhparser 提升专名召回。
- 异步：Celery 任务，失败重试、状态可查（运维台）。

## 3. 混合检索（含密级/权限过滤）

### 3.1 链路
```
query + context{caller_scope, max_clearance}
  → 关键词召回 tsvector+zhparser (top-N)
  → 向量召回 pgvector HNSW (top-N)
  → RRF 融合
  → 权限下推过滤:
       WHERE permission_tags && caller_scope        -- 数组交集
         AND security_level <= max_clearance         -- 密级上限
  → Rerank Qwen3-Reranker-0.6B (top-50)
  → top-K
```

### 3.2 过滤语义（我方标准）
- `permission_tags[]`：元素 `scope:<type>:<value>`，`type∈{dept,role,user,group}`。
- `caller_scope[]`：同格式，表示调用方可见范围。
- 可见条件：chunk 的 `permission_tags` 与 `caller_scope` **存在交集** 且 `security_level ≤ max_clearance`。
- 过滤在 DB 层执行，越权/超密级不进模型。

## 4. 生成与推理编排

```
/v1/generate(task, doc_type, query, elements, context)
  → 检索增强(带过滤) → top-K 上下文(含引用)
  → 模板装配(8类文种骨架)
  → Qwen3-32B 生成，Prompt 强制:
      ① 公文规范表述 ② 事实须引用上下文 ③ 无依据标[待核实]
  → 引用标注: 事实陈述插 [n] 指向原文切片
  → 敏感词后处理: 命中词 mask/flag
  → 返回 {answer, citations[], sensitive_hits[], hallucination_flag}
```

### 4.1 幻觉抑制
- 上下文约束（禁编造事实/数据/文号）；引用强制；评测闭环（幻觉率 ≤3%）。

### 4.2 ModelProvider 抽象
```python
class ModelProvider(ABC):
    def chat(self, messages, **kw): ...
    def embed(self, texts): ...
    def rerank(self, query, docs): ...
# LocalProvider / CloudProvider / StdProvider(部署方算力中心, 标准接口)
# prod 启动自检: 检测到 CloudProvider -> exit(1)
```

### 4.3 起草参考文档（按上传文档的模板格式生成 / 仿写）

- 场景：调用方上传自己的历史公文（红头文件/上行文/行业模板），**不选平台预置文种模板**，要求"照这个格式/写法出新公文"。
- 流程：`POST /v1/generate/reference` 上传（DOCX/PDF/OFD/TXT/MD，≤20MB）→ 提取**版式画像**（页边距/题名字体字号对齐/红头/正文众数中文字体/标题字体/结构大纲）→ 返回 `reference_id`；起草（`/v1/generate`）带 `reference_id` + `reference_mode`：
  - `format`：仅套用版式格式；`imitate`：仅仿写内容与结构；`both`：格式+仿写（缺省按画像自动选择）；
  - 三种模式均向生成模型注入自然语言「参考文档要求」提示词（结构大纲/字体/红头约束）。
- 导出（`/v1/export/docx`）带同一 `reference_id`：DOCX 渲染版式优先级 **参考文档 > 模板 layout > GB/T 9704 默认**（字体/页边距/红头来自画像）。
- 与知识库**解耦**：参考文档不切分、不向量化、不进检索语料，仅保存画像与原件引用（`draft_references` 表，迁移 0016）；画像失败直接 400 不落库。
- 所有权：仅上传者本人（user/client）可引用，他人 `404`；SSE 链路上的加载错误在响应头发出前返回，保证 4xx 可正常交付。

## 5. 模板库（我方维护）

- 文种模板 8 类：通知/通报/报告/请示/函/纪要/决定/意见。
- 模板结构：`{skeleton(版式骨架), required_fields(必填要素), example_anchors(引用锚点), style_ref(样式/字体)}`。
- 管理：我方维护；支持第三方**导入提供模板样式**（版式/字体/落款规范）。
- 生成时由模板引擎装配骨架，再交 LLM 填充表述。

---

## 6. 导出服务（我方提供下载接口）

- 接口：`POST /v1/export`（入参：内容/草稿 + 模板选择 + 格式）或 `GET /v1/export/{id}?format=docx|pdf`。
- 渲染：docx 用 python-docx（套用公文字体：仿宋_GB2312 正文、方正小标宋标题、黑体小标题、楷体引文，已授权）；pdf 用 WeasyPrint/LibreOffice 无头转换，字体嵌入。
- 导出前再次敏感词/密级校验；受限内容按权限拦截。
- ofd：二期。

---

## 7. 敏感词引擎（我方配置 + 应用）

- 配置：词集 CRUD（`/v1/config/sensitive-words`），可选 `action∈{mask, flag}`；支持请求级覆盖（`context.sensitive_words` 或 `config_id`）。
- 应用：生成输出扫描命中 → mask(■■■)/flag → 回报 `sensitive_hits`；检索上下文可选提示。
- 主库在第三方；我方为执行与应用方。

---

## 8. 权限与合规（执行我方标准）

- 入库：文档带 `security_level` + `permission_tags`（按我方标准，第三方提供数据）。
- 查询：请求带 `caller_scope` + `max_clearance`，服务端 `WHERE` 下推。
- 审计：caller 标识、时间、文档、命中密级分布、动作，全留痕。

## 10. 核心数据模型

```sql
document (
  id, external_id, title, doc_type, issuer, doc_no, publish_date,
  security_level,            -- 我方标准枚举
  permission_tags text[],    -- scope:<type>:<value>[]
  owner_org, source_system,
  original_path, status, tenant, created_at
);
chunk (
  id, document_id, seq, content, content_vec vector(1024),
  tsvector_col, security_level, permission_tags text[], char_count
);
template (id, doc_type, skeleton, required_fields, example_anchors, style_ref, owner);
config_sensitive_words (id, word, action, tenant, enabled);
config_format_adapter (id, system_name, field_mapping jsonb, rules, enabled);
config_model_profile (id, name, provider_type, base_url, api_key, model_name, capabilities[], dims, enabled);
audit_log (id, caller, action, doc_ids, clearance_used, ts, trace_id);
```
