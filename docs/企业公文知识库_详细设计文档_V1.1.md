## 1. 系统定位与范围边界

### 1.1 我方 vs 第三方职责边界

```
┌──────────────────────────────────────────────────────────────┐
│            第三方 公文系统（权威源 / 调用方）                    │
│  组织架构·部门树 │ 用户与认证 │ 权限主数据 │ 密级定义          │
│  导出渲染 │ 敏感词主库 │ 公文起草前端 │ 工作流                │
└───────────────────────────┬──────────────────────────────────┘
              │ 内部网络 API（携带调用上下文：权限范围/密级上限/敏感词集）
              ▼
┌──────────────────────────────────────────────────────────────┐
│         我方 RAG 引擎服务（被集成）                             │
│  文档解析 │ 切片入库 │ 混合检索 │ 推理生成 │ 引用溯源          │
│  密级/权限过滤（执行） │ 敏感词应用（执行） │ 配置中心 │ 运维台 │
└──────────────────────────────────────────────────────────────┘
```

| 能力 | 归属 | 说明 |
|---|---|---|
| 组织架构 / 部门树 | 第三方 | 我方不建模，仅消费其下发的"可见范围" |
| 用户身份与认证 | 第三方 | 我方信任上游网关传递的调用上下文 |
| 文档权限主数据 | 第三方 | 入库时随文档带来权限标签；查询时随请求带来可见范围 |
| 密级定义与标注 | 第三方 | 文档入库带密级标签；查询带"可阅密级上限" |
| 敏感词主库 | 第三方（主） | 我方"支持配置"：可管理一份配置集，也接受请求级覆盖 |
| 导出（docx/pdf/ofd） | 第三方 | 我方输出结构化答案+引用，交由第三方渲染导出 |
| 公文起草前端 | 第三方 | 调用我方 `/generate` 获取草稿与引用 |
| **文档解析** | **我方** | 多格式解析 + 格式适配配置 |
| **切片入库** | **我方** | 切片 + 上下文前缀 + Embedding + PG 存储 |
| **检索推理** | **我方** | 混合检索 + 生成 + 溯源；并执行密级/权限/敏感词过滤 |
| 配置中心 / 运维台 | **我方** | 敏感词配置、格式适配配置、入库监控、评测 |

### 1.2 信任边界与安全假设

- 我方**不重新认证终端用户**；身份由第三方网关保证，请求中携带已鉴权的调用上下文（`caller_scope`、`max_clearance`）。
- 我方与第三方之间**仅内网互通**；我方推理/应用**禁止出网**（三层防护不变）。
- 密级/权限过滤**必须在服务端基于传入上下文强制执行**，不能依赖第三方"不问就不给"——这是防泄露核心，与 V1.0 一致（检索阶段下推）。
- 所有调用（接入/检索/推理/配置）留审计日志，供第三方追溯。

## 5. 文档接入与解析流水线

### 5.1 接入方式（配置驱动）

- **推送 API**：`POST /v1/documents`（单篇/批量），请求体携带文档原文（或 对象存储（本地文件系统 / S3 兼容） 引用）**及元数据**（见第 7 章契约）。
- **文件投放**：目录/SFTP 轮询 + CSV 元数据映射（适合离线批量）。
- **格式适配配置**：不同"公文系统导出格式"通过**格式适配器配置**适配，无需改代码（第 12 章）。

### 5.2 元数据来源（第三方下发，我方不生成）

入库文档随附：`doc_type`(文种)、`issuer`(发文机关)、`doc_no`(文号)、`publish_date`、`security_level`(密级)、`permission_tags`(权限/可见范围标签)、`source_system`、`owner_org`。

### 5.3 流水线

```
源(第三方推送/批量投放) → [解析] PDF(文字层)/docx/wps转docx/[OCR后路预留]
   → [结构化抽取] 标题/机关/文号/日期/文种/正文分段（含第三方元数据）
   → [清洗] 归一化、去页眉页脚噪声
   → [切片] 语义分块≈500字/重叠50字，前缀注入【标题｜机关｜文号｜日期｜路径】
   → [向量化] Qwen3-Embedding-4B → 1024维
   → [入库] document + chunk(含 vector/tsvector/security_level/permission_tags)
   → [索引] HNSW + tsvector(zhparser)
```
入库任务经 Celery 异步，失败重试、可追溯，运维台可见进度。

## 6. 检索引擎与混合检索

方案：**PostgreSQL + pgvector + zhparser**（单库统一元数据+关键词+向量；BSD 许可最干净；Milvus 仅作未来升级路径）。

```
查询(query + 调用上下文{caller_scope, max_clearance})
   ├─[关键词召回] tsvector+zhparser → BM25近似 (top-N)
   └─[向量召回]   pgvector HNSW → 余弦 (top-N)
        → [RRF 融合]
        → [权限下推过滤] WHERE permission_tags ⊇ caller_scope AND security_level ≤ max_clearance
        → [重排] Qwen3-Reranker-0.6B (top-50)
        → top-K 上下文
```
**权限/密级过滤在检索 SQL 的 WHERE 中强制下推**，越权/超密级切片在数据库层即排除，不进入生成。自定义词典（单位名/项目代号）注入 zhparser 提升专名召回。

## 7. 集成接口契约（核心新增）

> 第三方与我方之间的全部交互约定。字段名为建议，最终以双方联调确认为准。

### 7.1 通用约定

- 协议：HTTPS（内网）+ JSON；鉴权：网关令牌 / mTLS；版本：`/v1/`。
- 所有请求由第三方网关注入调用上下文（身份已由第三方鉴权）。
- 我方响应统一包：`{code, message, data, trace_id}`。

### 7.2 文档接入

`POST /v1/documents`
```json
{
  "docs": [
    {
      "external_id": "第三方主键",
      "title": "关于...的通知",
      "doc_type": "通知",
      "issuer": "XX公司办公厅",
      "doc_no": "XX函〔2025〕12号",
      "publish_date": "2025-03-01",
      "security_level": "内部 | 受限 | 秘密",   // 第三方密级枚举
      "permission_tags": ["dept:总部","role:公文员"], // 第三方可见范围
      "owner_org": "XX部门",
      "source_system": "公文系统V2",
      "content_ref": "storage://bucket/xxx.pdf"   // 或内联 content 文本
    }
  ]
}
```
响应：`{accepted: N, failed: M, task_ids: [...]}`，入库异步，状态可查。

### 7.3 检索

`POST /v1/retrieve`
```json
{
  "query": "安全生产责任追究",
  "context": {
    "caller_scope": ["dept:总部","role:公文员"], // 第三方下发的可见范围
    "max_clearance": "受限",                     // 可阅密级上限
    "tenant": "optional"
  },
  "top_k": 10
}
```
响应 `data`：`[{chunk_id, doc_id, doc_no, title, snippet, score, citation}]`，**已过滤越权/超密级**。

### 7.4 推理 / 问答（起草辅助）

`POST /v1/generate`
```json
{
  "task": "draft | qa | continue",
  "doc_type": "通知",                 // 可选，用于套模板
  "query": "起草一份关于汛期值班安排的通知",
  "elements": {"主送":"各分公司","要点":["带班领导","24小时值守"]}, // 用户要素
  "context": {
    "caller_scope": ["dept:总部"],
    "max_clearance": "受限",
    "sensitive_words": ["可选：请求级覆盖词表 或 config_id"],
    "tenant": "optional"
  }
}
```
响应 `data`：
```json
{
  "answer": "各分公司：...[1]...[2]",
  "citations": [
    {"marker":"[1]","doc_no":"XX函〔2025〕12号","title":"...","chunk_id":"...","snippet":"..."}
  ],
  "sensitive_hits": [{"word":"XXX","action":"masked","position":[12,15]}],
  "hallucination_flag": false
}
```
> 我方输出**结构化答案 + 引用 + 敏感词命中**；第三方据此渲染导出。

### 7.5 配置（我方"支持配置"的能力面）

`GET/PUT /v1/config/sensitive-words`（敏感词集 CRUD）
`GET/PUT /v1/config/format-adapters`（公文系统导出格式适配配置）
`GET/PUT /v1/config/tenants`（可选多租户配置）

## 8. 权限与密级执行（消费第三方上下文）

- **入库**：文档的 `security_level` 与 `permission_tags` 由第三方随文档带来，我方原样存储并建索引。
- **查询**：请求携带 `caller_scope`（可见范围）与 `max_clearance`（密级上限），检索 WHERE 强制 `permission_tags 匹配 caller_scope AND security_level ≤ max_clearance`。
- **不下推的后果**：等于越权/超密级内容已进模型上下文——属失效控制，必须杜绝。
- **审计**：谁（第三方 caller 标识）、何时、查了哪篇、命中密级分布，全留痕。

---

## 9. 敏感词控制（我方"支持配置"并应用）

- **配置**：我方维护可配置的敏感词/禁用词集（配置中心 API/运维台管理），并支持请求级覆盖（第三方可传 `sensitive_words` 或引用 `config_id`）。
- **应用位置**：
  1. **生成输出后处理**：对 `answer` 扫描命中词，执行 `mask`（■■■）或 `flag`，并在 `sensitive_hits` 中回报；
  2. **检索上下文（可选）**：对将送入模型的 top-K 片段做命中提示，避免泄露放大。
- **不负责主库治理**：敏感词"主库"在第三方；我方是执行与应用方。

## 10. 生成与推理编排

```
第三方调用 /generate（task, doc_type, query, elements, context）
   → [检索增强] 按 context 过滤检索 → top-K 上下文（含引用）
   → [模板装配] 载入该文种模板骨架（8类）
   → [生成] Qwen3-32B：基于"模板+上下文+要素"，Prompt 强制：
        ① 公文规范表述 ② 事实须引用上下文 ③ 无依据标[待核实]
   → [引用标注] 每处事实性陈述插 [n] 指向原文切片
   → [敏感词后处理] 命中词 mask/flag
   → [合规校验] 格式/文号校验
   → 返回结构化 {answer, citations, sensitive_hits}
```
**幻觉抑制三机制**：上下文约束 + 引用强制 + 评测闭环（幻觉率 ≤3%）。

**ModelProvider 抽象**：`dev=CloudProvider` / `prod=LocalProvider`；生产启动自检拒绝云端 Provider；网络封死出口。

## 13. 核心数据模型（概要）

```sql
document (
  id, external_id, title, doc_type, issuer, doc_no, publish_date,
  security_level,          -- 来自第三方
  permission_tags,         -- 来自第三方（数组）
  owner_org, source_system,
  original_path(对象存储（本地文件系统 / S3 兼容）), status, tenant, created_at
);
chunk (
  id, document_id, seq, content(含上下文前缀), content_vec(vector(1024)),
  tsvector_col, security_level, permission_tags, char_count
);
config_sensitive_words (id, word, action, tenant, enabled);
config_format_adapter (id, system_name, field_mapping, rules, enabled);
```

## 15. 实施里程碑（服务化 MVP）

| 阶段 | 目标 | 验证门禁 |
|---|---|---|
| M0 环境 | 国产 OS + PG+pgvector+zhparser + 对象存储（本地文件系统 / S3 兼容） + vLLM 起通 | `env_smoke.py` 全绿 |
| M1 入库质量 | 30 篇种子入库，切片/向量/检索可用 | 检索准确率 ≥85% |
| M2 检索+过滤 | 混合检索 + 密级/权限下推过滤 | 越权/超密级召回 = 0；P95 ≤800ms |
| M3 推理+溯源 | 8 类文种 + 生成 + 引用溯源 + 敏感词后处理 | 格式合规 ≥95%；幻觉 ≤3%；敏感词命中全 mask |
| M4 配置+运维 | 敏感词配置、格式适配器配置、运维台 | 新增格式免改代码；配置生效 |
| M5 联调 | 与第三方按第 7 章契约联调 | 密级/权限/敏感词端到端验证通过 |

> 关键路径：**M1 知识库质量决定上限**；**M5 集成契约**是服务化成败点，需尽早与第三方对齐字段。
