### 0.2 真实样本体检结论（决定工期的关键数据）

对 `sichuan_gov_docs/` 30 篇真实公文运行 `tools/sample_audit.py` 实测：

- 100% PDF；**96.7% 有文字层，仅 1 篇 1 页需 OCR** → **OCR 不再是工期瓶颈**，流水线仅需预留后路；

## 1. 总体架构

### 1.1 设计原则

1. **模块化单体优先**：单一部署单元、内部分层模块，Docker Compose 一把起。200 用户 / 20 并发不需要服务拆分带来的分布式复杂度。
2. **模型可替换**：所有模型调用经 `ModelProvider` 抽象，云端/本地切换仅改配置，业务代码零改动。
3. **权限过滤前置（检索阶段下推）**：涉密/越权内容在召回阶段即被过滤，**绝不进入模型上下文**——生成后再过滤等于内容已泄露。
4. **引用溯源强制**：生成内容的事实性陈述必须带角标指向原文切片；无依据时系统必须明确提示，不允许静默编造。
5. **涉密不出网（三层防护）**：Provider 隔离 → 生产启动自检（检测到云端 Provider 直接拒绝启动）→ **网络策略封死出口**（唯一不依赖应用正确性的防线）。

## 4. 文档接入与处理流水线

### 4.1 流水线（异步、可重试）

```
源文件(公文系统导出/批量导入/单文件上传)
   │
   ▼
[解析]  PDF(有文字层→pdfplumber/PyMuPDF 提文本) / docx(python-docx) / wps(转 docx)
   │     扫描件/无文字层 → 走 OCR 后路(PaddleOCR，预留，本期样本无需)
   ▼
[结构化]  抽取：标题、发文机关、文号、日期、文种、主送机关、正文分段
   │
   ▼
[清洗]   去页眉页脚/水印噪声、全角半角归一、冗余空白
   │
   ▼
[切片]   按公文语义分块(章/节/段)，chunk≈500 字，重叠 50 字
   │     ★ 每个切片前缀注入【标题｜发文机关｜日期｜文号｜标题路径】
   ▼
[向量化] Qwen3-Embedding-4B → 1024 维向量（离线/批量）
   │
   ▼
[入库]   PostgreSQL：document 表 + chunk 表(含 vector 列) + 元数据 + 权限标签
   │
   ▼
[索引]   pgvector HNSW 索引 + tsvector(zhparser) 关键词索引
```

### 4.2 切片上下文前缀（提升中文公文召回的关键一招）

每个 chunk 存储时拼接结构化前缀，使向量与关键词检索都能命中"谁发的、什么文种、哪年"：

```
[标题：关于XXX的通知｜发文机关：XX公司办公厅｜文号：XX函〔2025〕12号｜日期：2025-03-01｜路径：通知/2025/12号]
<正文切片内容...>
```

### 4.3 公文系统导出接入

- 提供 **SFTP / 共享目录轮询** 或 **REST 推送接口** 两种接入方式（用户确认"无集成要求"，故以文件级接入为主，不强制系统对接）；
- 批量导入支持目录拖入 + CSV 元数据映射（文号、文种、密级、部门由 CSV 关联）；
- 入库任务经 Celery 异步，失败可重试、可追溯，运营后台可见进度。

### 4.4 自定义词典（zhparser）

把**单位全称、部门名、项目代号、专有名词**注入 zhparser 用户词典，显著提升机构专名与精确数字的召回（公文高频查询）。

## 5. 检索引擎决策与混合检索设计（核心）

### 5.1 方案比选

| 候选 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| OpenSearch/ES | BM25+向量成熟，IK 分词强 | SSPL/Elastic License 信创审查有争议；需与向量库配合才完整 | 放弃 |
| Milvus | 向量规模/性能强，GPU 检索 | 纯向量，关键词仍需另配；当前 193 万规模过度设计 | 仅作未来升级路径 |
| **PostgreSQL+pgvector+zhparser** | 单库统一元数据+关键词+向量；BSD 许可最干净；可换国产 PG 系；运维最简 | BM25 为 ts_rank 近似；超大并发需调优（本规模无所谓） | **采用** |

### 5.2 混合检索链路

```
用户查询
   │
   ├─[关键词召回] tsvector + zhparser → BM25 近似打分 (top-N)
   └─[向量召回]   pgvector HNSW(ANN) → 余弦相似度 (top-N)
                        │
                        ▼
              [RRF 融合] Reciprocal Rank Fusion 合并两路结果
                        │
                        ▼
        [权限下推过滤] 按用户角色/部门/密级标签过滤（召回阶段，非生成后）
                        │
                        ▼
        [重排] Qwen3-Reranker-0.6B 对 top-50 逐条重排
                        │
                        ▼
                  top-K 上下文 → 生成编排
```

### 5.3 权限下推实现

- `chunk` 表携带 `dept_scope`（部门可见范围）、`security_level`（密级标签）、`owner_org`；
- 检索 SQL 在 `WHERE` 中直接叠加当前用户的数据权限表达式（来自 RBAC 解析），**越权/高密级切片在数据库层即被排除**，不进入后续任一环节；
- 这是防泄露的核心防线，绝不在生成后再做"隐藏"。

## 6. 生成与起草编排

### 6.1 起草流程（S1 智能起草）

```
用户选择文种 + 填写要素(主送机关/事由/要点) 或 上传素材
   │
   ▼
[检索增强] 按要素检索知识库 → 召回相关范文/条款/表述（含引用溯源）
   │
   ▼
[模板装配] 载入该文种模板骨架 → 填充结构
   │
   ▼
[生成] LLM(Qwen3-32B) 基于"模板+检索上下文+用户要素"起草
   │     Prompt 强制：① 使用公文规范表述 ② 事实/表述须引用上下文 ③ 无依据则标注[待核实]
   ▼
[引用标注] 每处事实性内容自动插入角标 [n] 指向原文切片，附溯源列表
   │
   ▼
[合规校验] 敏感词/禁用词扫描 + 格式校验(文号/落款/字体)
   │
   ▼
[用户编辑] 工作台内可改、可重新生成局部、可查看溯源
   │
   ▼
[导出] docx / pdf（字体已授权，保真）
```

### 6.2 幻觉抑制三机制

1. **上下文约束**：Prompt 明确要求"只能基于检索上下文与用户给定要素，禁止编造事实、数据、文号"；
2. **引用强制**：事实性陈述必须带 `[n]`；模型输出无对应检索依据时，系统侧注入 `[待核实]` 提示；
3. **评测闭环**：`retrieval_eval` / `generation_eval` 离线评测幻觉率（目标 ≤3%），纳入回归。

### 6.3 ModelProvider 抽象（云端↔本地零改动切换）

```python
class ModelProvider(ABC):
    @abstractmethod
    def chat(self, messages, **kw): ...
    @abstractmethod
    def embed(self, texts): ...
    @abstractmethod
    def rerank(self, query, docs): ...

# 配置切换：dev=CloudProvider(云端API)  prod=LocalProvider(vLLM本地)
# 生产启动自检：若 prod 环境检测到 CloudProvider → 拒绝启动
```

## 7. 权限与合规设计

### 7.1 三维权限模型

- **RBAC**：角色（管理员/公文员/审核员/普通用户/只读/访客等）；
- **数据权限**：部门/组织树范围（文档可见性按 `dept_scope` 下推）；
- **轻量密级**：内部/受限/秘密（企业秘密级）标签，仅做检索过滤与导出管控，**非分保级**。

### 7.2 三层防泄露（对应"涉密不出网"）

1. **Provider 隔离**：云端/本地实现分离，配置即切换；
2. **启动自检**：生产环境加载到 CloudProvider 直接 `exit(1)` 拒绝启动；
3. **网络策略**：推理服务与应用服务器**出口封死**，仅靠内网互通；这是唯一不依赖应用正确性的硬防线。

### 7.3 审计

所有检索、生成、导出操作留痕（谁、何时、哪篇文档、何操作），运营后台可查，满足内网合规追溯。

## 9. 导出设计

- **docx**：python-docx 套用公文字体（仿宋_GB2312 正文、方正小标宋标题、黑体小标题、楷体引文，均已授权）；
- **pdf**：WeasyPrint / LibreOffice 无头转换，字体嵌入保证保真；
- **ofd**：二期（用户确认可延后）；
- 导出时再次执行敏感词/密级校验，受限内容按权限拦截。

## 10. 核心数据模型（概要）

```sql
-- 文档主表
document (
  id, title, doc_type(文种), issuer(发文机关), doc_no(文号),
  publish_date, source, security_level, dept_scope, owner_org,
  original_path(对象存储（本地文件系统 / S3 兼容）), status, created_at

-- 切片表（含向量）
chunk (
  id, document_id, seq, content(含上下文前缀), content_vec(vector(1024)),

);

-- 文种模板
template (id, doc_type, skeleton, required_fields, example_anchors);

-- 权限
role, user_role, org_tree, user_data_scope;
```

|---|---|---|
| 检索延迟 | P95 ≤ 800ms（含重排） | HNSW + RRF + 0.6B 重排；Redis 热点缓存 |
| 起草耗时 | 首稿 ≤ 30s（32B-INT4） | vLLM 连续批处理；上下文 top-K 截断 |
| 容量 | 20 万文档 / 193 万切片 | 512GB NVMe；pgvector 单表可扩展 |
| 可用性 | 单机 99.5%（无 HA 要求） | Docker Compose 重启策略；PG 定时备份 |
| 安全 | 涉密不出网 | 三层防护 + 审计 |
| 信创 | OS/DB 国产可替换 | PG→openGauss 平滑；国产 OS 部署验证 |
| 易用性 | 起草工作台零学习成本 | 文种向导 + 要素表单 + 溯源可视 |

## 12. 实施里程碑与验证门禁（MVP）

| 阶段 | 目标 | 验证门禁 |
|---|---|---|
| M0 环境 | 国产 OS + PG+pgvector+zhparser + 对象存储（本地文件系统 / S3 兼容） + vLLM 本地起通 | 自检脚本 `env_smoke.py` 全绿 |
| M1 知识库质量 | 30 篇种子入库，切片/向量/检索可用 | 检索准确率 ≥85%（`retrieval_eval`） |
| M2 检索 | 混合检索 + 权限下推 + 重排 | 越权召回 = 0；P95 ≤ 800ms |
| M3 起草 | 8 类文种模板 + 生成 + 引用溯源 | 格式合规率 ≥95%；幻觉率 ≤3% |
| M4 导出/运营 | docx/pdf 导出 + 运营后台 | 导出保真达标；审计完整 |
