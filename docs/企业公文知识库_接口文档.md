# 企业公文智能写作知识库平台 · 接口文档（含标准规范）

> 配套《详细设计文档 V1.2》《项目架构文档》《详细功能设计文档》
> 最后更新：2026-10-09
> 说明：以下接口与字段标准**由平台制定**，集成方（第三方/部署方）须适配。

---

## 1. 通用约定

- Base：`https://<部署域内网>/v1/`
- 协议：HTTPS（内网）；鉴权：网关令牌 `Authorization: Bearer <token>` 或 mTLS。
- 响应包：`{ "code": 0, "message": "ok", "data": ..., "trace_id": "..." }`；`code≠0` 为错误。
- 所有请求由上游网关注入调用上下文（身份已由第三方鉴权），我方不重认证终端用户。
- 字符集 UTF-8；时间 ISO-8601。

---

## 2. 我方制定的字段与枚举标准

### 2.1 文档元数据标准（接入必带）
| 字段 | 类型 | 说明 |
|---|---|---|
| external_id | string | 第三方主键（幂等依据） |
| title | string | 标题 |
| doc_type | string | 文种：通知/通报/报告/请示/函/纪要/决定/意见 |
| issuer | string | 发文机关 |
| doc_no | string | 文号 |
| publish_date | date | 日期 |
| security_level | enum | 见 2.2 |
| permission_tags | string[] | 见 2.3 |
| owner_org | string | 归属组织 |
| source_system | string | 来源系统标识 |
| content_ref | string | 对象存储（本地文件系统 / S3 兼容） 引用，或内联 `content` 文本 |

### 2.2 密级枚举（我方标准）
`PUBLIC`(公开) / `INTERNAL`(内部) / `RESTRICTED`(受限) / `SECRET`(秘密/涉密)
> 第三方将自身分级**映射**到上述四级；检索以我方枚举判定上限。

### 2.3 权限标签格式（我方标准）
元素：`scope:<type>:<value>`，`type ∈ {dept, role, user, group}`。
示例：`["scope:dept:总部", "scope:role:公文员"]`。
检索可见条件：`chunk.permission_tags && caller_scope`（数组交集非空）且 `chunk.security_level <= max_clearance`。

## 3. 文档接入

`POST /v1/documents`
```json
{
  "docs": [
    {
      "external_id": "OA-2025-0001",
      "title": "关于汛期值班安排的通知",
      "doc_type": "通知",
      "issuer": "XX公司办公厅",
      "doc_no": "XX函〔2025〕12号",
      "publish_date": "2025-03-01",
      "security_level": "INTERNAL",
      "permission_tags": ["scope:dept:总部", "scope:role:公文员"],
      "owner_org": "办公厅",
      "source_system": "公文系统V2",
      "content_ref": "storage://docs/2025/0001.pdf"
    }
  ]
}
```
响应：`{ "accepted": 1, "failed": 0, "task_ids": ["t-abc"] }`（入库异步）。
`GET /v1/documents/tasks/{task_id}` → 任务状态/进度。

## 4. 检索

`POST /v1/retrieve`
```json
{
  "query": "安全生产责任追究",
  "context": {
    "caller_scope": ["scope:dept:总部", "scope:role:公文员"],
    "max_clearance": "RESTRICTED",
    "tenant": "optional"
  },
  "top_k": 10
}
```
响应 `data`：
```json
[
  {
    "chunk_id": "c-123", "doc_id": "d-1", "doc_no": "XX函〔2025〕12号",
    "title": "关于...的通知", "snippet": "...", "score": 0.91,
    "citation": { "doc_no": "...", "title": "...", "chunk_seq": 3 }
  }
]
```
> 已过滤越权/超密级；`caller_scope` 与 `max_clearance` 缺失则拒绝（code=400）。

## 5. 推理 / 问答（起草辅助）

`POST /v1/generate`
```json
{
  "task": "draft",
  "doc_type": "通知",
  "query": "起草一份关于汛期值班安排的通知",
  "elements": { "主送": "各分公司", "要点": ["带班领导", "24小时值守"] },
  "context": {
    "caller_scope": ["scope:dept:总部"],
    "max_clearance": "RESTRICTED",
    "sensitive_words": ["可选：请求级覆盖词表 或 config_id"],
    "tenant": "optional"
  }
}
```
响应 `data`：
```json
{
  "answer": "各分公司：...[1]...[2]",
  "citations": [
    { "marker": "[1]", "doc_no": "XX函〔2025〕12号", "title": "...", "chunk_id": "c-123", "snippet": "..." }
  ],
  "sensitive_hits": [ { "word": "XXX", "action": "masked", "position": [12, 15] } ],
  "hallucination_flag": false
}
```

## 6. 标准模型接入接口（部署方算力中心须实现）

> 我方通过 `ModelProvider(StdProvider)` 对接。部署方算力中心**暴露以下标准端点**（兼容 OpenAI 风格），或在其前加兼容网关；无需改我方代码即可接入自有模型。

### 6.1 Chat Completions（生成）
`POST {base_url}/v1/chat/completions`
```
Headers: Authorization: Bearer <token>, Content-Type: application/json
Body:   { "model": "<name>", "messages": [{"role":"system|user|assistant","content":"..."}],
          "temperature": 0.3, "max_tokens": 4096, "stream": false }
Resp:   { "choices": [{"message":{"role":"assistant","content":"..."},"finish_reason":"stop"}],
          "usage": {"prompt_tokens":0,"completion_tokens":0} }
```

### 6.2 Embeddings（向量）
`POST {base_url}/v1/embeddings`
```
Body:   { "model": "<name>", "input": ["text1","text2"] }
Resp:   { "data": [{"index":0,"embedding":[0.01,...]}], "model":"<name>" }
```

### 6.3 Rerank（重排，可选）
`POST {base_url}/v1/rerank`
```
Body:   { "model":"<name>", "query":"...", "documents":["...","..."] }
Resp:   { "results": [{"index":0,"score":0.93}, {"index":1,"score":0.81}] }
```
> 部署方若未提供 rerank，我方回退至 RRF 融合分排序。

### 6.4 ModelProfile 配置（我方配置中心）
```json
{
  "name": "客户算力中心-A",
  "provider_type": "std",
  "base_url": "https://gpu-center.internal/v1",
  "api_key": "***",
  "model_name": "self-hosted-qwen3-32b",
  "capabilities": ["chat","embed","rerank"],
  "dims": 1024,
  "enabled": true
}
```
provider_type ∈ {local, cloud, std}。`local`=我方默认 Qwen3 栈；`cloud`=开发期云端；`std`=部署方算力中心（标准接口）。

## 7. 模板库（我方维护，支持第三方导入）

`GET/POST/PUT/DELETE /v1/templates` — 模板 CRUD；`doc_type` 为键。
`POST /v1/templates/import` — 第三方导入提供模板样式（版式/字体/落款）。

---

## 8. 导出下载（我方提供）

`POST /v1/export`
```json
{ "content": "<生成内容或草稿>", "template_id": "tpl-notice-01", "format": "docx" }
```
响应：文件流（或 `{ "download_url": "...", "file_id": "..." }`）。
`GET /v1/export/{file_id}` — 下载已生成文件（docx/pdf）。
> 导出前执行敏感词/密级校验；受限内容按权限拦截。

---

## 9. 配置接口

`GET/PUT /v1/config/sensitive-words` — 敏感词集 CRUD。
`GET/PUT /v1/config/format-adapters` — 公文系统导出格式适配配置。
`GET/PUT /v1/config/model-profiles` — 模型接入配置。

## 10. 错误码标准

| code | 含义 |
|---|---|
| 0 | 成功 |
| 400 | 参数缺失/非法（如缺 caller_scope/max_clearance） |
| 401 | 鉴权失败 |
| 403 | 越权/超密级（不应发生，过滤后为空时也返回空而非 403） |
| 404 | 资源不存在 |
| 409 | external_id 重复 |
| 422 | 文档解析/格式适配失败 |
| 429 | 限流 |
| 500 | 内部错误 |
| 503 | 模型后端不可用（算力中心未就绪） |
