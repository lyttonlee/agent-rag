## 1. 文档目的与边界

### 1.1 目的

本文回答三个问题：

1. **平台提供什么功能**——功能全景清单（第 3 章）；
2. **怎么接入**——按接入深度分三档，第三档（私有化部署级）的完整接入方法（第 4 章）；
3. **接口怎么调**——全部端点的详细接口文档：请求参数（字段/类型/必填/默认/约束）、请求示例、响应字段类型、SSE 事件、错误码（第 5–7 章）。

### 1.2 边界

- 本文只覆盖**平台对外开放的能力**；平台内部实现（解析/切分/检索管线）见《详细设计文档 V1.2》《文档入库流程说明》。
- 平台运行于**部署方内网**，不提供公网服务；涉密内容不出网由部署方网络边界与我方启动自检共同保证。
- 平台**不重认证终端用户**：信任上游网关传入的调用方身份（JWT 或 API Key）与调用上下文（`caller_scope` / `max_clearance`）；但密级/权限过滤由平台**服务端强制执行**。
- 本文不承诺未列出的字段/端点；新增能力以版本号递增方式进入本文，客户端应**忽略未知字段与未知 SSE 事件**（向前兼容约定，见 5.1.7）。

## 2. 接入档位体系

平台按接入深度定义三档，部署方按自身情况选档；**本文完整覆盖第三档**，前两档在此定义以便选型。

| 档位 | 名称 | 接入内容 | 适用场景 | 工作量 |
|---|---|---|---|---|
| 第一档 | 接口联调 | HTTP API 直调：注册客户端 → 接入文档 → 检索/问答 | PoC 验证、联调期 | 小时级 |
| 第二档 | 业务集成 | 在第一档基础上嵌入业务系统：会话管理、模板选用、空间隔离、权限上下文、导出下载 | 生产环境业务集成 | 天级 |
| **第三档** | **私有化部署级接入** | **接管运行环境：基础设施部署、模型接入（算力中心标准接口）、存储选型、权限主数据对接、密级映射、前端嵌入、运维监控** | **政企内网私有化部署** | **周级** |

### 2.1 第三档与其他两档的关系

- 第一/二档解决"**调用**"问题；第三档解决"**落地运行**问题。
- 第三档交付物 = 平台镜像（Docker Compose）+ 部署方提供的四类资源（文档数据、模型、权限主数据、前端）。
- 第三档接入方通常同时是第二档的调用方（自己的业务系统调用平台 API）。

### 2.2 第三档职责边界

| 平台方（我方）提供 | 部署方（第三方）提供 |
|---|---|
| 平台全部代码与镜像（后端 + 运维台前端 + OFD 解析独立库） | 文档数据（按平台字段标准携带密级/权限） |
| 接口规范、字段标准、密级/权限枚举、模型接入标准 | 模型服务（可选自有算力中心，实现标准接口；或用平台本地 Qwen3 栈） |
| 文档解析 / 切片入库 / 检索推理 / 模板库维护 / 导出 / 配置中心 / 运维台 | 组织架构 / 认证 / 权限主数据（映射为 `scope:` 标签） |
| 启动自检（数据库 / 存储 / Embedding / Rerank）与排障提示 | 前端调用（可嵌入运维台，或自建前端调 API） |
| 密级/权限过滤执行（服务端 WHERE 下推）、敏感词配置与应用 | 网络隔离与出口封死（涉密不出网） |

## 4. 第三档接入方法

### 4.1 部署拓扑

```
┌────────────────────────── 部署方内网 ──────────────────────────┐
│                                                               │
│  第三方业务系统 ──HTTPS──► ┌────────── 平台（Docker Compose）┐  │
│  （或嵌入运维台前端）      │ 后端 API（FastAPI，:8000）       │  │
│                           │ 运维台前端（Vue3，:80 反代）     │  │
│                           └──────┬───────────────┬──────────┘  │
│                                  │               │             │
│                    ┌─────────────▼─┐   ┌─────────▼──────────┐  │
│                    │ PostgreSQL    │   │ 对象存储           │  │
│                    │ + pgvector    │   │ LocalFS（默认）/   │  │
│                    │ + zhparser    │   │ S3 兼容            │  │
│                    └───────────────┘   └────────────────────┘  │
│                                                               │
│   ┌──────────────────────┐   ┌──────────────────────────┐     │
│   │ 部署方算力中心（可选）│   │ 权限主数据 / 上游网关     │     │
│   │ Chat/Embed/Rerank    │   │ 下发 JWT 或 API Key +    │     │
│   │ 标准接口（OpenAI 风格）│   │ caller_scope/max_clearance│     │
│   └──────────────────────┘   └──────────────────────────┘     │
└───────────────────────────────────────────────────────────────┘
```

组件清单（最小集）：PostgreSQL 15+（pgvector + zhparser 扩展，镜像已定制）、后端服务、对象存储（LocalFS 零依赖起步，可切 S3 兼容）、模型服务（本地 Qwen3 栈或部署方算力中心）。

### 4.2 网络与安全边界

- 平台仅监听内网；**生产环境（`ENVIRONMENT=production`）启动自检拒绝 cloud 模型 Provider**——涉密不出网的第一道闸。
- 部署方负责网络出口封死（模型/存储/数据库全部内网可达）。
- API Key 服务端仅存 sha256 哈希，明文仅注册时返回一次；客户端可被 admin 即时禁用（止血）。

### 4.3 认证（双模，强制）

| 调用方 | 认证头 | 获取方式 |
|---|---|---|
| 运维台用户 | `Authorization: Bearer <JWT>` | `POST /v1/auth/login`，默认 12 小时有效 |
| 第三方系统（机对机） | `X-API-Key: sk-xxxx` | `POST /v1/auth/clients/register`，**明文仅返回一次** |

- 任一通过即放行（Bearer 优先）；全部 `/v1/*` 业务端点强制认证。
- **开放端点**（无需认证）：`POST /v1/auth/login`、`POST /v1/auth/clients/register`、`GET /health`、`GET /docs`、`GET /redoc`、`GET /openapi.json`。
- 认证失败统一 `401`，响应体 `{"detail": "..."}`；不区分"账号不存在/口令错误"（防枚举）。

### 4.4 能力域与密级额度

**能力域（scopes）**：`chat` / `retrieve` / `documents` / `spaces` / `conversations` / `templates` / `config` / `audit` / `ops`，或 `["*"]` 全开。缺失对应域 → `403`。按最小必要原则分配（如只做问答的系统给 `["chat","retrieve","conversations"]`）。

**密级额度（max_clearance）**：见第 6 章六级映射。用户按角色映射（`admin`→机密，其余→内部）；客户端注册时指定。请求体声明的 `max_clearance` **不得超过调用方额度**，超出自动压低（服务端强制）。

### 4.5 调用上下文（检索/生成必带）

- `caller_scope`：调用方权限标签（`scope:<type>:<value>`，`type ∈ {dept, role, user, group}`），由部署方权限主数据映射而来。例：`["scope:dept:总部", "scope:role:公文员"]`。
- `max_clearance`：本次请求的密级上限（被额度压低后生效）。
- 平台按"文档密级权重 ≤ 上限 **且** 权限标签与 caller_scope 有交集（或无标签）"做服务端 WHERE 下推；**过滤后为空返回空列表（非 403）**。

### 4.6 模型接入（部署方算力中心）

平台通过 `ModelProvider(std)` 对接部署方算力中心。算力中心（或其前置网关）暴露三个 **OpenAI 兼容风格**端点：

| 端点 | 用途 | 必需性 |
|---|---|---|
| `POST {base_url}/v1/chat/completions` | 生成（Qwen3-32B 级） | 必需 |
| `POST {base_url}/v1/embeddings` | 向量（入库一次性 + 查询） | 必需 |
| `POST {base_url}/v1/rerank` | 重排 | 可选（缺失则回退 RRF 融合分排序） |

请求/响应格式见 5.14 节。接入方式：在配置中心写 `model_profile`（5.11 节），`provider_type="std"`，保存即时生效，无需重启。平台默认栈为本地 Qwen3（Embedding-4B / Reranker-0.6B / 生成 32B-INT4），`provider_type ∈ {local, cloud, std}`。

> **模型能力要求（深度推理相关）**：深度推理每轮要求模型输出**单个 JSON 对象**。若部署方模型对结构化输出支持较弱，可在提示词面板（5.7）加强约束，或关闭深度推理（`deep_reason=false`）回退普通问答。

### 4.7 存储接入

- **默认 LocalFS**：文件落服务器磁盘，零额外组件，适合单机部署。
- **S3 兼容**（SeaweedFS / Ceph RGW / 国产对象存储）：配置 `STORAGE_PROVIDER=s3` + endpoint/ak/sk/bucket，经 boto3 接入；两种模式对 API 完全透明（`content_ref` 语义一致）。
- 存储内容：上传原文（按 `raw/{doc_id}.{ext}`）、模板原件。

### 4.8 权限主数据对接

1. 部署方在其权限系统维护组织架构（部门/角色/用户/用户组）；
2. 接入文档时把权限对象写为 `permission_tags`（平台标准格式 `scope:type:value`）；
3. 上游网关在每次请求下发调用方的 `caller_scope`（该用户可见的标签集合）；
4. 平台在检索/问答/生成/导出全链路执行交集判定。

> 平台不存储也不解析部署方的组织架构，只认标准标签——权限主数据的维护成本留在部署方侧，平台保持无状态。

### 4.9 前端嵌入（两种方式）

1. **直接用运维台**：平台自带 Vue3 运维台（文档库/检索/问答/深度推理/起草/模板/配置/运维监控等视图），部署后即可用；
2. **嵌入自建前端**：自建页面调平台 API（第二档能力），或把运维台作为静态资源嵌入门户 iframe。文档库上传弹窗支持 PDF/DOCX/OFD/TXT 四种格式。

## 5. 详细接口文档

### 5.1 通用约定

#### 5.1.1 基础约定

| 项 | 约定 |
|---|---|
| Base | `https://<部署域内网>/v1/` |
| 协议 | HTTPS（内网）；请求/响应均 UTF-8；`Content-Type: application/json`（文件上传为 `multipart/form-data`） |
| 时间格式 | ISO-8601 带时区，例 `2026-10-19T08:30:00+00:00`；仅日期字段用 `YYYY-MM-DD` |
| 认证 | `Authorization: Bearer <JWT>` 或 `X-API-Key: sk-xxxx`（双模，见 4.3） |
| 成功响应 | 直接返回该端点响应 Model JSON（**无 `code/data` 外层包装**） |
| 失败响应 | `{"detail": "<错误描述>"}` + HTTP 状态码（见第 7 章）；参数校验失败由 FastAPI 返回 422 结构化详情 |
| 分页 | 列表端点用 `page`（从 1 起）+ `size`（1–200）；**部分列表端点直接返回数组、不返回总数**（见各端点说明） |
| 幂等 | 文档接入以 `external_id` 为幂等键；配置中心 PUT 为 upsert；其余 POST 非幂等 |
| 超时建议 | 普通请求 30s；检索 60s；流式问答/起草不设客户端总超时（按事件空闲超时判定，建议 120s） |
| 字符上限 | 单请求 body 建议 ≤ 10MB；文件上传 ≤ 50MB（可按部署配置调整） |

#### 5.1.2 字段类型约定

| 类型记法 | 含义 | JSON 示例 |
|---|---|---|
| `string` | UTF-8 字符串 | `"通知"` |
| `int` | 32/64 位整数 | `8` |
| `float` | 浮点数（相关度、距离） | `0.9134` |
| `bool` | 布尔 | `true` |
| `datetime` | ISO-8601 字符串 | `"2026-10-19T08:30:00+00:00"` |
| `enum` | 取值受限的字符串（枚举值见附录 B） | `"INTERNAL"` |
| `string[]` | 字符串数组 | `["scope:dept:总部"]` |
| `T \| null` | 可为 null | `null` |
| `object` | 任意 JSON 对象（结构见上下文） | `{"value": 8}` |

#### 5.1.3 SSE 帧格式

流式端点（`/v1/chat/stream`、`/v1/generate/stream`）返回 `Content-Type: text/event-stream`，每帧：

```
data: {"type":"token","text":"根据"}\n\n
```

- **一帧一个 JSON**，`type` 为判别字段；客户端必须按 `type` 分发（**未知 type 必须忽略**，不得报错）。
- 无 `id:` / `event:` 行（不使用 SSE 命名事件）；不使用 `retry:`。
- 响应头含 `Cache-Control: no-cache`、`Connection: keep-alive`、`X-Accel-Buffering: no`（禁用 Nginx 缓冲）。
- 客户端断开（AbortController）会触发服务端保存已生成部分为助手消息。

#### 5.1.4 幂等与并发

| 场景 | 行为 |
|---|---|
| `POST /documents/ingest` 相同 `external_id` | 返回 `status="duplicate"`，不重复入库（HTTP 200） |
| `POST /documents/upload` 相同 `external_id` | 任务直接置 `INDEXED` 并关联已有文档，`error_message` 给出可读提示 |
| `PUT /config/items`、`PUT /chat/react/prompts` | upsert 语义，重复提交结果一致 |
| 同一会话并发问答 | 不推荐；平台按消息顺序落库，可能产生交错历史 |

#### 5.1.5 空间所有权（服务端强制）

- 第三方/用户创建的空间**仅创建者本人可见、可上传、可检索**；他人空间列表/详情不可见（`404`，不暴露存在性）、上传 `403`、纳入检索 `403`。
- 空间 owner 由服务端按调用方身份写入，**不接受客户端指定**。
- 默认空间固定 ID `spcdefault0000000000000000000000`（system 公共空间：所有人可见、可上传）。

#### 5.1.6 脱敏与免责声明

- 敏感词在**生成后**统一脱敏：返回 `sensitive_hits[]`（命中的词条），正文中已替换为掩码。
- 无材料的兜底回答与深度推理回答统一附 `disclaimer=true`，前端应展示「AI 生成，请人工鉴别」。

#### 5.1.7 版本兼容约定

- **响应可增字段**：客户端不得因出现未知字段而失败。
- **SSE 可增事件**：老客户端忽略未知 `type` 即兼容（本文标注"新增"的事件均属此类）。
- **请求字段不删**：字段废弃先标记 deprecated，至少保留一个大版本。

> 文档空间是知识库的逻辑分区（支持层级，类似文件夹）。文档归属空间，检索/问答可按 `space_ids` 限定范围。默认空间固定 ID `spcdefault0000000000000000000000`。

**响应 HTTP 201（`SpaceResp`）：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 空间 ID |
| `name` | string | 名称 |
| `code` | string | 编码 |
| `description` | string \| null | 描述 |
| `is_default` | bool | 是否默认公共空间 |
| `parent_id` | string \| null | 父空间 ID |
| `owner_type` | enum | `system` / `user` / `client` |

#### 5.3.2 列表 / 详情 / 更新 / 删除

- `GET /v1/spaces` → **`SpaceResp[]`**（默认空间置顶；**仅返回默认空间 + 本人创建的空间**）。

- `PUT /v1/spaces/{space_id}` — 请求体（`SpaceUpdate`，字段均选填）：

  | 字段 | 类型 | 约束 | 说明 |
  |---|---|---|---|
  | `name` | string \| null | 1–128 | 新名称 |
  | `description` | string \| null | ≤512 | 新描述 |
  | `parent_id` | string \| null | 合法空间 | `null` 表示移到根级 |

  **响应：** `SpaceResp`。仅创建者可更新（`403`）；默认空间仅 admin 可改名、不支持移动（`409`）；防环校验（`409`）。
- `DELETE /v1/spaces/{space_id}` → `{"deleted": "<space_id>"}`。
  保护策略（均 `409`）：默认空间不可删；空间内仍有文档不可删；仍有子空间不可删。

**SSE 事件总表（普通问答 + 深度推理共用；`type` 为判别字段）：**

| `type` | 字段（类型） | 出现条件 | 说明 |
|---|---|---|---|
| `phase` | `phase`(enum)、`label`(string)、`round`(int,可选)、`tool`(string,可选) | 全流程 | **阶段播报**：`start`/`classify`/`understand`/`decide`/`tool`/`answer`；用于消除静默期，前端应展示"正在做什么 + 已等待 Ns" |
| `meta` | `conversation_id`(string)、`model`(string)、`intent`(enum)、`intent_label`(string)、`agent_mode`(bool)、`no_result`(bool)、`citations`(`Citation[]`) | 每次请求一次 | 会话与检索元数据 |
| `plan` | `steps`(`Step[]`)、`channel`(string) | `complex_task` | 拆分计划（过程可见）。`Step = {id, action(retrieve\|generate), query, status}` |
| `step_start` | `id`(string)、`action`(string)、`query`(string) | 分步执行 | 某步骤开始 |
| `step_end` | `id`(string)、`ok`(bool)、`summary`(string) | 分步执行 | 某步骤结束（`ok=false` 时 `summary` 为失败原因） |
| `token` | `text`(string) | 生成阶段 | 正文增量 |
| `reasoning` | `text`(string) | 生成阶段 | 模型思考链增量（可能数百条，前端需节流渲染） |
| `react_start` | `mode`(string="react")、`max_rounds`(int)、`unlimited_rounds`(bool)、`total_budget_ms`(int)、`tools`(string[]) | 深度推理开始时 | **`max_rounds=0` 且 `unlimited_rounds=true` = 不限轮数（默认）** |
| `analysis` | `restate`(string)、`needs_knowledge`(bool)、`needs_knowledge_reason`(string)、`candidates`(string[])、`ambiguities`(string[]) | 深度推理理解阶段 | 提问理解结果（**仅供参考，不构成路由**） |
| `react_round` | `round`(int)、`max_rounds`(int)、`unlimited_rounds`(bool) | 每轮开始 | 轮次开始 |
| `thought` | `round`(int)、`text`(string) | 每轮 | 本轮思考（完整文本，勿截断展示） |
| `action` | `round`(int)、`tool`(string)、`query`(string)、`skipped`(bool) | 每轮有工具动作时 | `skipped=true` 表示去重/未知工具/缺参，未真实执行 |
| `observation` | `round`(int)、`tool`(string)、`query`(string)、`hits`(`ObsHit[]`)、`quality`(object)、`note`(string)、`elapsed_ms`(int)、`hits_total`(int) | 工具执行后 | 观察结果。`ObsHit = {n, chunk_id, document_id, title, doc_no, snippet, full_snippet, score}` |
| `react_end` | `rounds`(int)、`stop_reason`(enum)、`stop_label`(string)、`citations_total`(int)、`total_ms`(int) | 循环结束时 | 停止原因见下表 |
| `done` | `conversation_id`(string)、`answer`(string)、`sensitive_hits`(string[])、`model`(string)、`intent`(enum)、`no_result`(bool)、`disclaimer`(bool) | 正常结束 | 完整答案（脱敏后） |
| `error` | `message`(string) | 异常 | `"{异常类型}: {摘要}"` |

**`stop_reason` 枚举（`react_end`）：**

| 值 | `stop_label` | 含义 | 客户端建议 |
|---|---|---|---|
| `final` | 信息充分（模型主动结束） | 模型判断信息已足够，主动收尾 | 正常 |
| `max_rounds` | 达到轮数上限 | **仅在运维显式配置了轮数硬闸时出现**（默认不出现） | 正常（提示可提高上限） |
| `budget` | 超出时间预算 | 仅显式配置了 `deep_budget_ms` 时出现 | 正常（提示可放开预算） |
| `no_progress` | 连续多轮无新材料，已强制收尾 | 连续 `no_progress_limit` 轮无新增引用 | 正常（答案仍会完整生成） |
| `parse_fail` | 决策输出连续不可解析 | 模型连续 2 次输出非法 JSON | 建议检查模型结构化输出能力 |
| `decision_fail` | 决策调用连续失败 | 模型连续 2 次调用异常/超时 | 建议检查模型服务健康度 |

**意图（`intent`）枚举**：`direct_qa`（单轮直答）、`complex_task`（复杂任务分步）、`draft`（问答场景的起草诉求）、`deep_reason`（深度推理）、`chitchat`（寒暄，固定话术）、`out_of_scope`（超范围，明确拒答）。

> 深度推理默认全开：`deep_reason` 缺省时，`direct_qa`/`complex_task` 会被编排层改写为 `deep_reason`；`chitchat`/`out_of_scope`/起草不受影响。显式 `deep_reason=false` 完全回退普通问答。

#### 5.6.4 深度推理问答（ReAct）行为说明

**它和普通问答的区别**

| 维度 | 普通问答 | 深度推理（ReAct） |
|---|---|---|
| 检索次数 | 固定 1 次（`direct_qa`）或按拆步计划（`complex_task`） | **模型逐轮决定**，可 0 次也可多轮 |
| 工具选择 | 代码固定 | 模型从 3 个工具中自主选择 |
| 轮数 | 固定/计划定死 | **默认不限**，模型判断信息足够即收尾 |
| 过程可见 | 只有检索结果 | `thought`/`action`/`observation` 全量推送，可回看 |

**三个工具的契约**（`react_start.tools` 与提示词面板一致）

| 工具名 | 参数 `query` 语义 | 返回 |
|---|---|---|
| `knowledge_search` | 检索问题/关键词（一次一个点） | 命中片段摘要 + 质量信号（向量距离/关键词命中数/top1 分） |
| `doc_lookup` | 文档标题/文号/关键词 | 文档元数据（不含正文），用于定位"该看哪份文件" |
| `read_document` | 32 位 `chunk_id`（读该片+相邻片）或文档标题/文号（读原文） | 原文片段，按 4000 字符预算渐进返回；`note` 说明剩余量与建议 |

**轮数与收尾（V1.1 重要变更）**

- **默认不设轮数上限**（`deep_max_rounds=0`）：模型持续迭代直到自己 `finish`，因此"需要 3 轮就 3 轮、需要 12 轮就 12 轮"。
- **默认不设时长上限**（`deep_budget_ms=0`）：不再按 60s/180s 硬切。
- **收敛靠护栏**而非轮数：
  - `no_progress_limit`（默认 3）：连续 N 轮无**新增**引用 → 第 N-1 轮注入"换角度或收尾"提示，第 N 轮强制收尾（`stop_reason=no_progress`），随后照常生成完整答案；
  - 决策连续失败/JSON 连续不可解析各 2 次 → 收敛；
  - 运维仍可显式设置 `deep_max_rounds`/`deep_budget_ms` 正数作为硬闸（默认关闭）。
- **档位（`react_mode`）只影响检索广度**：`fast` 每轮召回 4 条、注入 4 条；`deep` 每轮召回 8 条、注入 8 条。两档轮数都不限。

**客户端处理建议**

1. 必须注册 `phase` 处理器并显示 `label`（否则前 10 秒页面像卡死）；
2. `thought`/`observation` 全文展示、不要单行截断（这是"思维链可见"的载体）；
3. `reasoning` 事件量大（单轮可达数百条），渲染需节流（建议 50–100ms 合并一次）；
4. 收到 `react_end` 后仍要等 `token` 流完，**不要在 `react_end` 就结束 UI 加载态**；
5. 历史回看：助手消息的 `reasoning` 字段已落库 TAO 全链文本，格式为 `【第N轮】思考：… → 调用：tool("q") → 观察：命中 N 条`，可直接折叠展示。

### 5.7 深度推理提示词配置（/v1/chat/react/prompts）

> 目的：让"模型到底被怎么指示"可见、可调，**无需改代码/发版**。三段提示词（理解/决策/最终生成）支持整段覆盖；观察消息模板是结构化逻辑，只读。

#### 5.7.1 读取提示词与运行参数

`GET /v1/chat/react/prompts` — 需认证

**Query 参数：**

| 参数 | 类型 | 必填 | 默认 | 说明 |

#### 5.7.2 保存 / 恢复提示词（admin）

`PUT /v1/chat/react/prompts` — 需 **admin 用户 JWT**

**请求体：**

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `prompts` | object[] | 是 | 至少 1 项 | 待保存列表 |
| `prompts[].key` | enum | 是 | 三个可编辑 key 之一 | 目标提示词 |
| `prompts[].content` | string | 是 | ≤20000 字符 | 提示词全文；**空字符串 = 恢复默认**（删除覆盖） |

**响应 HTTP 200：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `saved` | object[] | `[{key: string, content: string, source: "custom"\|"default"}]` |
| `message` | string | 固定提示语 |

**请求示例：**

```json
{
  "prompts": [
    {
      "key": "deep_prompt_decision",
      "content": "你是公文知识库智能体。每轮只输出一个 JSON（thought + action）。\n可用工具：\n{tool_lines}\n{round_rule}"
    }
  ]
}
```

**变量占位符**（保存时无需替换，运行时由服务端注入）：

| 占位符 | 适用提示词 | 注入内容 |
|---|---|---|
| `{tool_lines}` | 决策 | 工具清单（名称 + 参数语义） |
| `{max_rounds}` | 决策 | 轮数硬上限数字；不限时注入 `"不限"` |
| `{round_rule}` | 决策 | 收尾规则整段（不限轮/有上限两种措辞） |
| `{material_rule}` | 最终生成 | 材料使用规则（有材料=必须标注引用；无材料=不得拒答） |
| `{has_material}` | 最终生成 | `"有"` / `"无"` |

**错误**：

| HTTP | detail | 场景 |
|---|---|---|
| `400` | `未知提示词键：xxx（可用：…）` | key 不在白名单 |
| `400` | `提示词过长：{key} 共 N 字符，上限 20000` | 超长 |
| `403` | `需要管理员权限` | 非 admin |

> **写入语义**：先全量校验再逐条落库，任一段非法则整批不写入（避免"部分保存"的中间态）。保存后**下一次问答立即生效**（无需重启）。配置落库位置：`category=agent`、`key=deep_prompt_*`。

> 智能问答（chat）与公文起草（draft）共用会话体系；多轮上下文由后端在生成时自动拼接（历史轮次按 2000 字/条截断注入）。

#### 5.8.1 创建会话

`POST /v1/conversations` — 需认证

**请求体（`ConversationCreate`）：**

| 字段 | 类型 | 必填 | 默认 | 约束 | 说明 |
|---|---|---|---|---|---|

| `title` | string \| null | 否 | null | ≤256 | 标题（缺省由首轮问题生成） |

#### 5.8.2 列表 / 搜索

`GET /v1/conversations` — 会话列表（按最后活跃倒序）

**Query 参数（均选填，可组合）：**

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `conv_type` | enum | — | `chat` / `draft`，按类型过滤 |

| `limit` | int | `50` | 返回条数（1–200） |

**请求示例：**


### 5.9 模板库（/v1/templates）

> 平台维护 8 类标准公文模板（开箱即用）；同一文种支持多个模板（起草时用 `template_code` 精确选用）。
> **所有权隔离**：系统标准模板所有人可见、可引用起草，仅 admin 可维护；用户/第三方上传的模板仅创建者本人可见、可编辑、可删除。

- `GET /v1/templates` — 需认证 → **`ConfigItem[]`**。每项：

  | 字段 | 类型 | 说明 |
  |---|---|---|
  | `category` | string | 固定 `"template"` |
  | `key` | string | 模板编码 `code` |
  | `value` | object | 见下 |
  | `scope` | string \| null | 作用域 |
  | `is_active` | bool | 是否启用 |

  `value` 结构：`{doc_type, name, layout, content_ref, owner_type, owner_id, owner_name, is_mine, can_edit}`。
  `layout` 结构：`{red_head: bool, font: string, paper: string, subtitle: string, tone: string, sections: [{key, label, placeholder, required}]}`。

- `POST /v1/templates` — 需认证。**请求体（`ConfigItem`）：** `category="template"`、`key=<模板编码>`、`value={doc_type, name, layout}`。**响应：** 创建或更新后的 `ConfigItem`。更新他人模板或系统模板 → `403`。
- `POST /v1/templates/upload` — 需认证；`multipart/form-data`：

  | 字段 | 类型 | 必填 | 说明 |
  |---|---|---|---|
  | `file` | file | 是 | `docx`/`pdf`/`ofd`/`txt` |
  | `doc_type` | string | 否 | 文种（可空=自动识别） |
  | `name` | string | 否 | 模板名称（缺省用文件名） |

  每次上传作为**独立新模板**（自动生成 code，不覆盖同文种已有模板），归属上传方。**响应：** `ConfigItem`。
- `GET /v1/templates/{code}/file` — 需认证。下载模板原件（文件流；无上传文件 `404`；他人模板不可见 `404`）。
- `POST /v1/templates/seed` — 需认证，**限 admin**。初始化标准模板库（幂等）→ `{"added": int, "message": string}`。
- `DELETE /v1/templates/{code}` → `{"deleted": bool}`。仅创建者可删本人模板；系统模板限 admin；他人模板 `403`。

### 5.10 导出下载（/v1/export）

`POST /v1/export/docx` — 需认证（scopes 含 `chat` 或 `*`）

**请求体（`ExportDocxRequest`）：**

| 字段 | 类型 | 必填 | 默认 | 约束 | 说明 |
|---|---|---|---|---|---|
| `conversation_id` | string | 是 | — | 已存在会话 | 定位已生成的起草内容 |

| 一级标题 | 黑体 | 三号 16pt | 无缩进，段前距 |
| 二级标题 | 楷体_GB2312 | 三号 16pt | 无缩进 |
| 正文 | 仿宋_GB2312 | 三号 16pt | 首行缩进 2 字符，固定行距 28 磅，两端对齐 |
| 列表 | 仿宋_GB2312 | 三号 16pt | 悬挂缩进 |

#### 5.14.1 Chat Completions（生成，必需）

`POST {base_url}/v1/chat/completions`

```
Headers: Authorization: Bearer <token>, Content-Type: application/json
```

## 6. 密级与权限过滤行为（重点）

### 6.1 六级密级映射（平台标准）

| 枚举值 | 中文名 | 权重 | 定位 |
|---|---|---|---|
| `PUBLIC` | 非密 | 1.0 | 可对外公开 |
| `INTERNAL` | 内部 | 2.0 | 内部资料（默认） |
| `COMMERCIAL` | 普通商密 | 2.3 | 一般商业秘密 |
| `CORE_COMMERCIAL` | 核心商密 | 2.7 | 核心商业秘密 |
| `CLASSIFIED` | 密级 | 3.0 | 受控密级资料 |
| `TOP_SECRET` | 机密 | 4.0 | 最高密级 |

权重全序：`1.0 < 2.0 < 2.3 < 2.7 < 3.0 < 4.0`（仅用于服务端可见性比较）。

**兼容规则**（存量接入零改造）：

- 历史四级代码自动归一：`RESTRICTED` → `COMMERCIAL`、`SECRET` → `TOP_SECRET`；
- 中文名直传自动归一：`非密`/`内部`/`普通商密`/`商密`/`核心商密`/`密级`/`机密`；
- 大小写不敏感；
- 存量数据库由启动迁移自动转换（序位一致，可见性关系不变）。

### 6.2 可见性判定（服务端强制）

文档/切片可见 ⇔ **同时**满足：

1. **密级条件**：`security_level` 权重 ≤ 调用方 `max_clearance` 权重；
2. **权限条件**：`permission_tags` 与调用方 `caller_scope` 存在交集；或文档无任何权限标签（全局公开，仅受密级约束）；调用方无 scope 时仅可见无权限约束的内容。

过滤在**检索阶段服务端 WHERE 下推**——涉密/越权内容在数据库层即被排除，**不进入模型上下文**；不是生成后过滤。过滤后为空返回空列表（非 403）。导出口岸同样复核（所引文档密级超额 → `403`）。

> **深度推理同样受此约束**：`knowledge_search`/`doc_lookup`/`read_document` 三个工具均在数据库层带上密级/权限条件，模型无法通过"换个工具"绕过。

### 6.3 典型配置示例

| 场景 | 配置 |
|---|---|
| 只读公开知识的问答机器人 | scopes=`["chat","retrieve","conversations"]`，max_clearance=`PUBLIC` |
| 全量知识库的公文起草 | scopes=`["*"]`，max_clearance=`CORE_COMMERCIAL` |
| 含涉密文件的知识管家 | scopes=`["*"]`，max_clearance=`TOP_SECRET`（对应 admin 用户） |

| 200 | 成功 | — |
| 201 | 创建成功 | — |
| 400 | 参数缺失/非法 | `content 与 content_ref 至少提供一个` / `未知提示词键：xxx` / `提示词过长：…` |
| 401 | 鉴权失败 | `需要登录凭证（Bearer JWT）或 API Key（X-API-Key）` / `用户名或口令错误` / `API Key 无效或已禁用` / `API Key 已过期` / `未登录或登录已过期` |
| 403 | 越权 | `该客户端无 <域> 能力域权限` / `需要管理员权限` / `无权使用该模板（仅创建者与系统标准模板可用）` / `导出内容含超出您密级额度的引用，已拒绝导出` / `无权访问他人文档空间` |
| 404 | 资源不存在 | `文档不存在` / `会话不存在` / `会话不存在：<id>` / `客户端不存在` / `文档空间不存在：<id>` / 他人空间/任务（不暴露存在性） |
| 409 | 冲突 | `external_id 重复` / `空间编码已存在：<code>` / `默认空间不可删除` / `空间内仍有 N 篇文档…` / `不能把空间移动到自己的子孙节点下` |
| 422 | 参数校验/格式失败 | Pydantic 校验详情；文档解析或格式适配失败 |
| 429 | 限流 | — |
| 500 | 内部错误 | 异常摘要 |
| 503 | 模型后端不可用 | 算力中心未就绪 |

**流式端点的错误**：HTTP 头已发出后出错，通过 SSE `{"type":"error","message":"..."}` 下发（HTTP 状态仍为 200）；客户端必须以收到 `error` 或流结束作为终止条件。

## 8. 集成时序

### 8.1 最小联调链路（30 分钟）

1. `GET /health` 确认服务就绪；
2. `POST /v1/auth/clients/register` → 保存 `api_key`（一次性）；
3. `POST /v1/documents/ingest`（带 `X-API-Key`）接入一篇文档；
4. `POST /v1/retrieve` 验证检索命中；
5. `POST /v1/chat/stream` 验证问答（SSE；带 `deep_reason=true` 验证深度推理事件）；
6. `GET /v1/chat/react/prompts` 查看当前生效提示词；
7. `POST /v1/export/docx` 验证公文版式导出。

### 8.2 生产集成链路（第三档）

1. 基础设施：拉起 PostgreSQL（pgvector+zhparser）+ 存储（LocalFS/S3）+ 模型（本地栈或算力中心标准接口）；
2. 启动自检四项全绿（db/storage/embedding/rerank）；
3. 配置中心：写 `model_profile`（std 接入）、检索参数、敏感词、提示词；
4. **深度推理调参**：确认 `deep_reason_enabled=true`、`deep_max_rounds=0`（不限轮数）、按需调整 `deep_no_progress_limit`；必要时通过 `/v1/chat/react/prompts` 调整三段提示词；
5. 权限主数据：部署方把组织架构映射为 `scope:` 标签；上游网关下发 JWT/API Key + `caller_scope`/`max_clearance`；
6. 文档批量接入（`/ingest` 幂等或 `/upload` 异步），轮询任务状态至 `INDEXED`；
7. 业务系统调用检索/问答/起草/导出；历史用 `/conversations?keyword=` 检索；
8. 运维：`/v1/audit/logs` 留痕审计，`/health` 与运维台监控。

## 10. 常见问题（FAQ）

**Q1：上传返回 200 但文档搜不到？**
上传是异步入库：轮询 `/v1/documents/jobs/{job_id}` 至 `INDEXED` 才算完成（`FAILED` 看 `error_message`，常见为解析失败）。

**Q2：检索结果为空但确认库里有文档？**
依次排查：① `space_ids` 是否限定了非本人空间（403 或空）；② `caller_scope` 与文档 `permission_tags` 无交集；③ `max_clearance` 低于文档密级（`truncated_by_security=true` 即此因）。过滤后为空返回空列表而非 403。

**Q3：历史会话太多，如何定位某一轮？**
`GET /v1/conversations?keyword=<关键字>`（标题+消息内容模糊搜，命中消息返回高亮片段），或 `GET /v1/conversations?id=<完整会话ID>` 精确直达。

**Q4：导出的 docx 能带模板版式吗？**
可以：`template_code` 指定模板，其 `layout.font`（正文字体）/`red_head`（红头）会应用到导出；系统标准模板与本人创建的模板可用。

**Q5：重复接入同一篇文档会怎样？**
`/ingest` 返回 `status="duplicate"`（不重复入库）；`/upload` 重复 `external_id` 直接置 `INDEXED` 并关联已有文档（跳过切分/向量化）。

**Q6：想用自己的模型？**
在配置中心写 `model_profile`（`provider_type="std"`，指向算力中心），实现 5.14 三个标准端点即可；缺 rerank 自动回退 RRF，不影响主链路。

**Q7：旧系统按四级密级（RESTRICTED/SECRET）传参，升级后会 422 吗？**
不会。服务端自动归一（RESTRICTED→普通商密、SECRET→机密），存量接入零改造；数据库存量行由启动迁移自动转换。

**Q8：深度推理为什么默认"不限轮数"？会不会跑飞？**
V1.1 取消轮数上限，是为了让模型按问题难度自行决定检索深度（固定 2/5 轮会把复杂问题截断）。防跑飞靠三道护栏：① 连续 `no_progress_limit`（默认 3）轮无新材料强制收尾；② 决策连续失败/JSON 连续不可解析各 2 次收敛；③ 运维可随时把 `deep_max_rounds`/`deep_budget_ms` 设为正数作为硬闸。**不限轮 ≠ 无限空转**。

**Q9：`react_start` 里 `max_rounds=0` 是什么意思？**
**不限轮数**（不是 0 轮）。同时返回 `unlimited_rounds=true`，客户端据此显示"不限"即可。

**Q10：改了提示词不生效？**
① 确认是 `PUT /v1/chat/react/prompts` 成功（响应 `source="custom"`）；② 确认用的是正确的 `key`；③ 保存即生效，无需重启；④ 若在配置中心直接改了**已废弃**的旧键（如 `deep_deep_max_rounds`），不会生效——请用 5.11 的新键。

**Q11：提示词里能用 `{tool_lines}` 这类占位符吗？**
可以，且推荐。决策提示词支持 `{tool_lines}`/`{max_rounds}`/`{round_rule}`；最终生成支持 `{material_rule}`/`{has_material}`。未引用的占位符保持原样；决策提示词若未引用 `{tool_lines}`，服务端会自动追加工具清单。
